## Эфиры YouTube

1. Выдели мышью строку нужного канала. Галочки других строк не определяют канал запуска эфира.
2. Нажми **«Запустить эфир»**. В заголовке окна должен быть именно выделенный канал.
3. Выбери папку видео, название, описание, JPG/PNG-превью, теги через запятую, доступ и аудиторию.
4. Нажми **«Запустить эфир»**. Если привязки ещё нет, приложение само проверит сессию указанного профиля Dolphin. Существующее подключение также проверяется при запуске передачи.
5. Для первой привязки нужен корректный URL канала в строке либо явный `@handle` в её названии. Канал, открытый в Studio, сверяется с этим адресом/сохранённым ID. При несовпадении запуск прекращается; не подменяй ожидаемый канал произвольным текущим каналом профиля.
6. Во время передачи кнопка выделенного канала становится **«Завершить эфир»**. Она останавливает этот канал. Отдельное действие остановки всех эфиров сохранено.

Колонка «Эфир» скрыта; состояние доступно через кнопку и подсказку строки. Передача идёт локальным FFmpeg с этого ПК в YouTube по RTMPS. Для продолжения эфира ПК и приложение должны работать.

Выбора 720p/1080p больше нет. Ширина, высота и FPS берутся из исходных файлов, включая вертикальное видео и дробный FPS. Файлы одной папки должны иметь одинаковые размеры и FPS: несовместимая папка получает понятную ошибку до запуска передачи. H.264/AAC готовятся для непрерывной передачи; это сохраняет геометрию/FPS, но не означает побитовое копирование исходного кодека. Отсутствующий звук заменяется тишиной.

Название: до 100 символов. Описание: до 5000 **байт UTF-8**, без `<`/`>`. Теги: до 500 символов суммарно, включая запятые-разделители и дополнительные кавычки для тегов с пробелом. В окне есть счётчик. Это ограничение длины списка, а не фиксированное количество тегов.

Проверка на ПК: в тестовой таблице отметь галочкой канал A, а выдели строку канала B. Убедись, что окно относится к B. Без реального запуска можно закрыть окно. Затем проверь один эфир на своём тестовом канале: совпадение канала, название, теги, сохранение превью, источник размера/FPS, старт, остановка и отсутствие незавершённой передачи. Ключ RTMPS и данные сессии не выводи в отчёт.

## TikTok

Основная кнопка: **«Опубликовать через Dolphin»**. Быстрая HTTP-загрузка убрана из интерфейса, публичный HTTP-метод загрузки отключён. Старые диагностические модули оставлены для совместимости; вызывать их для публикации не нужно.

Порядок действий загрузчика:

1. Открывается нужный профиль Dolphin и нативная страница TikTok Studio для загрузки.
2. Выбирается локальный видеофайл, ожидается готовность загрузки.
3. Исходная подпись/имя файла удаляется. Подпись из существующего банка RU или EN вводится клавиатурой, с переносами строк. Прочитанный обратно текст должен совпасть.
4. Проверяются **«Сейчас / Now»** и **«Все / Everyone»**.
5. Перед нажатием публикации приложение сохраняет состояние, запрещающее повтор при потере ответа.
6. Нажимается **«Опубликовать / Post»** один раз. Если появляется **«Продолжить публикацию? / Continue publishing?»**, подтверждается публикация, а не отмена.
7. Через страницу **«Публикации / Posts»** определяется новая запись с её стабильным ID. Записи, существовавшие до нажатия, не считаются результатом новой публикации.
8. **«Контент проверяется»** означает статус **«На проверке»**, даже если TikTok временно показывает **«Только я»**. ID сохраняется сразу. Только подтверждённый доступ «Все» без признака проверки даёт статус **«Опубликовано для всех»**.
9. Ожидание проверки ограничено десятью минутами. Дальше запись остаётся «На проверке», профиль остаётся открыт, автоматического повторного поста нет. Кнопка **«Обновить статусы»** проверяет сохранённые ID отмеченных аккаунтов без загрузки файлов.

Банки подписей RU/EN и распределение материалов сохранены. Подпись ограничена 4000 символами, как в показанном пользователем интерфейсе. Новый путь публикует сейчас; ранее сохранённые записи отложенных публикаций не удаляются и не перепубликуются.

Если после нажатия результат неизвестен и ID не получен, оставь блокировку повтора и проверь Studio вручную. Не превращай любую ошибку или тайм-аут в повторную загрузку. Старое ручное действие сверки предназначено для таких неизвестных результатов; для записей с подтверждённым ID «На проверке» используй «Обновить статусы».

Проверка на ПК: один свой тестовый ролик в профиле RU и один в EN. Проверь удаление исходной подписи, точный текст с пустой строкой/эмодзи, режим сейчас/для всех, диалог подтверждения, сохранение ID, проверку и переход к публичному статусу. Закрой и открой приложение: запись и запрет повтора должны сохраниться. Обновление статуса не должно добавлять второй ролик.

Селекторы проверены на изолированных страницах в настоящем Chromium. Реальную текущую разметку TikTok Studio необходимо проверить в пользовательском Dolphin. Если она отличается, адаптируй локаторы по видимой странице, сохраняя описанный порядок и проверку результата. Не добавляй прямые запросы публикации и не помечай успех только по нажатию кнопки.

## Превью YouTube

Оба пути YouTube используют общий модуль выбора именно поля изображения в редакторе превью. Случайный первый `input[type=file]`, который может оказаться полем видео, больше не используется. Проверяется новая картинка и сообщение ошибки Studio. Для уже созданного ролика нажимается «Сохранить» и проверяется сохранённая картинка после перезагрузки страницы. В обычном мастере загрузки картинка проверяется до завершения мастера. В эфире также используется этот общий модуль и последующая проверка сохранённых данных.

Удалён старый безусловный пропуск превью для Shorts. На дату проверки официальная инструкция YouTube разрешает загрузку пользовательского превью Shorts в Studio с ПК: https://support.google.com/youtube/answer/72431?co=GENIE.Platform%3DDesktop&hl=en. Фактическая доступность поля зависит от функций канала. Для ПК принимаются JPG/PNG до 50 МБ; если Studio отклоняет файл, приложение сообщает ошибку.

В HTTP-пути видео может уже успешно загрузиться до отдельного шага превью. Если превью не подтвердилось, приложение показывает **«Видео загружено · превью не подтверждено»**, сохраняя результат загрузки. Не загружай такое видео повторно: исправляй превью у существующего ID. Для черновика ошибка также явно сообщает, что черновик уже создан.

Проверка на ПК: один обычный ролик и один Short на своём тестовом канале, с легко узнаваемым изображением. После загрузки открой нужный ID в Studio, перезагрузи страницу и проверь картинку. При отказе проверь доступ канала к пользовательским превью и сообщение Studio. Сохрани ID и точную ошибку без cookies/токенов. Если сервер меняет параметры URL изображения, уточни сравнение идентичности по фактической сохранённой картинке, не ослабляя проверку до наличия любой миниатюры.
