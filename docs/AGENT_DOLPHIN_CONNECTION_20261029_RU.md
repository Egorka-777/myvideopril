# Dolphin не подключается: исправление 29.10.2026

Ветка: `fix/dolphin-local-api-20261029`. Основа: `main`, `fb06c102da80a7eb5cde4437ab96193a4a176b57`.

Маркер исправления: **`2026-10-29-dolphin-auth-v2`**. Сборка Studio в `worker.js` остаётся v21; изменение подключения имеет собственный маркер в журнале.

## Что установлено по исходникам

- Старый JS-загрузчик сначала перебирал все слушающие порты процессов Dolphin. Любой первый HTTP 401/403 или `success:false` немедленно объявлялся неверным API-токеном; до рабочего порта поиск не доходил.
- HTTP 200 без явного `success:true` принимался за успешную авторизацию. Так можно было выбрать служебный сервис вместо локального API.
- C# повторно посылал тот же запрос ради чтения HTTP-статуса; поиск процессов/портов мог блокировать UI. Окно проверки обрезало причину до длины строки статуса.

В исправлении сначала проверяются сохранённый порт и 3001, затем найденные порты Dolphin и прежний диапазон 3002–3020. К порту обращаемся один раз. Продолжение после 401/403/неоднозначного 200, отмена и общий лимит времени; логин подтверждается только успешным HTTP и JSON `success:true`. Неудачный поиск не оставляет случайный порт в задании. У проверки в интерфейсе — состояние «проверяю», освобождение кнопки в `finally`, полная причина в диалоге и журнале.

**Порт 63464 на скриншоте не доказывает, что это основной API и что токен неверный.** Исправлены подтверждённые дефекты кода; конкретный ответ Dolphin на этом ПК нужно проверить после обновления. Ручное открытие профиля не проверяет вход через локальный API.

Официальный контракт: `POST http://127.0.0.1:PORT/v1.0/auth/login-with-token`, JSON `{ "token": "..." }`, подтверждение `{ "success": true }`. Порт по умолчанию 3001, фактический API-порт смотрят в Health Dolphin: https://docs.dolphin-anty.com/en/api/basic-automation-dolphin-anty

## Агенту на этом ПК

1. Сохранить локальные изменения. Подтянуть исправление из указанной ветки в актуальный checkout, сохранив более новые изменения `main`. Не делать `reset --hard`, не откатывать приложение к старому EXE.
2. Выполнить:

   ```powershell
   node tests/dolphin_local_auth.js
   node tests/dolphin_session_regressions.js
   dotnet build VideoBatch.csproj -c Release -p:ApplicationIcon=
   ```

   C#-проверка: загрузить `bin/Release/net48/VideoBatch.exe` через `[Reflection.Assembly]::LoadFrom(...)` и вызвать `VideoBatch.DolphinLocalApiTests.RunSelfTests()`.

3. Остановить задания и закрыть VideoBatch. Обновить **фактически запускаемый комплект**: обязательно новый EXE и JS вместе. Из checkout после Release-сборки использовать существующий `scripts/Sync-StudioUploader.ps1 -KitRoot 'D:\VideoBatch\VideoBatch'` (или действительный путь ярлыка). Скрипт переносит EXE из `bin/Release/net48` и uploader; исторический EXE в корне не использовать. Профили, settings, материалы, токены и runtime Node не удалять.
4. Dolphin оставить запущенным. Открыть VideoBatch и нажать `↻`. В `diagnostics/app-YYYYMMDD.jsonl` папки данных приложения должны быть `connection_start`, `connection_probe`, `connection_end` и новый маркер. При успехе виден подтверждённый API-порт. Сохранённый рабочий токен менять без нового подтверждённого отказа не нужно.
5. Проверить подключение/проверку одного профиля. Публикацию видео для диагностики связи запускать не требуется. После успеха и после ошибки кнопка `↻` должна снова нажиматься.

## Если на ПК всё ещё не подключается

- Открыть **Health в Dolphin**, взять именно API-порт, не порт открытого браузера/CDP. Вписать его в поле Dolphin port, убрать фокус с поля для сохранения и повторить проверку.
- Прочитать все `connection_probe` одной проверки. Если порт не отвечает — проверить, какой процесс им владеет. Если есть HTTP 401/403 — записать факт с портом, не объявлять произвольный служебный порт доказательством негодного токена. Сверить токен/аккаунт уже на подтверждённом API-порте.
- Проверить путь запускаемого EXE и наличие нового маркера; обновлённый исходник не означает обновлённый portable-комплект.
- Перед следующими правками сохранить журнал этой проверки и полное сообщение. Не увеличивать таймауты и не добавлять новые схемы авторизации наугад. Токены, proxy-пароли и тела запросов в отчёт не копировать.

## Проверки и ограничения

JS-тест воспроизводит `3001 → 404`, `63464 → 401`, затем рабочий API; проверяет ложный HTTP 200, один запрос на порт, отсутствие секрета в логах, восстановление порта и лимит времени. C#-тест проверяет реальные HTTP-обработчики, JSON, продолжение после отказа, неоднозначный 200 и отмену. Существующий тест повторного подключения к Dolphin-профилю сохранён.

CI `Dolphin local API connection` собирает настоящее Windows-приложение, запускает JS/C# проверки и публикует пакет `Dolphin-Connection-Fix-20261029`. Это обновление существующего комплекта, а не полный portable-дистрибутив со всеми зависимостями.

Проверка на настоящем Dolphin пользователя из этой среды **не выполнялась**. Не выдавать fixture-тесты за успешное подключение на его ПК.
