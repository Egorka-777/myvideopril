# Исправление календаря Studio и восстановление описаний

Ветка: `fix/studio-schedule-chips-20261021`, основана на актуальном `main` — `35df3935c35e3c2802d68464def39147f6b9117f`.
Маркер worker и диагностики: **`2026-10-21-studio-chips-v8`**. Этот документ заменяет прежнюю инструкцию об отключении ввода описания.

## Установка

1. Остановить задания и закрыть VideoBatch. Сохранить резервную копию действующего EXE, DLL/runtimes, `tools/uploader` и настроек. Не удалять аккаунты, прокси, Telegram vault / сессии и браузерные профили.
2. В Actions открыть успешный запуск **YouTube Studio RU EN upload** именно этой ветки. Скачать **VideoBatch-Studio-Schedule-Update**, сверить `SOURCE_COMMIT.txt` с выбранным запуском.
3. Заменить EXE, приложенные DLL/runtimes и **все** JS-файлы `tools/uploader` из архива. Новый `studio-schedule-controls.js` обязателен: обновления одного `worker.js` недостаточно. Сохранить установленный `node.exe`; выполнить `npm ci --prefix tools/uploader --ignore-scripts` имеющимся Node/npm.
4. Не откатывать остальные функции к старому `main`: ветка включает текущие изменения аккаунтов, Telegram и описаний из `35df393`. При установке из исходников сначала `git fetch origin`, создать рабочую ветку от `origin/fix/studio-schedule-chips-20261021`, затем `dotnet build VideoBatch.csproj -c Release`. Местные изменения предварительно сохранить и объединить, без `reset --hard`.
5. В журнале задания проверить новый маркер. Если виден старый — проверить путь запущенного EXE и папку uploader, а не переимпортировать аккаунты.

## Что изменилось

- Календарь открывается через кнопку даты внутри контейнера. Наличие других `ytcp-dropdown-trigger` — категории или времени — не делает выбор неоднозначным.
- В открытом календаре используется его поле ввода даты. Формат сохраняется по текущему отображению RU/EN. После Enter поле может исчезнуть; проверяется дата в основной карточке, без обращения к удалённому полю.
- Если поле даты отсутствует, допустим только выбор однозначной полной даты либо однозначного дня в подтверждённом единственном месяце. Поиск числа по всему мастеру, выбор верхнего из одинаковых чисел и JS `.click()` убраны.
- Календарь закрывается перед сменой времени и пояса. Порядок на экране «Доступ»: **дата → время → часовой пояс**, затем повторная проверка даты и времени (смена пояса может сбросить время, например на 00:00). Время поддерживается как поле 24 часа, поле AM/PM, карточка со списком и редактируемое поле внутри всплывающего выбора. Выбирается точное время; ближайший вариант не подставляется.
- Сохраняется пояс ПК. Перед «Запланировать» сверяются дата и время на карточке; при подсказке «в прошлом» или несовпадении HH:mm загрузка останавливается с понятной ошибкой. После отправки итоговые дата, время, пояс, описание и превью проверяются в отдельной вкладке Studio.
- Результат времени читается из текста карточки, когда это кнопка, и из `value`, когда это input. Пустой `button.value` больше не считается пустым временем.
- Ввод описания из настроенной базы приложения **включён**. Для каждого задания используется описание из RU/EN-банка по существующей логике приложения; непустые банки, в том числе 20 загруженных описаний, не заменяются новыми текстами. Теги Studio сохраняют прежний режим.
- На шагах даты, пояса, времени и ожидания финальной кнопки есть сообщения журнала. Неопознанный вид поля завершает настройку ошибкой за ограниченное время, а не запускает бесконечные клики.
- Один обработчик диалогов обслуживает основную и проверочную вкладки. Перезагрузка незавершённого мастера отменяется. При ошибке/Stop CDP отключается; профиль и незавершённый мастер сохраняются. Автоматический Stop/Restart уже открытого профиля без CDP для Studio отключён.

## Проверка на ПК

1. Сначала один отмеченный аккаунт и один согласованный ролик. Убедиться, что настроенный банк описаний не пуст, и запустить «Через Studio» с согласованным будущим временем.
2. Проверить ввод заголовка и описания, превью, переход в «Доступ», выбор даты, закрытие календаря, время, пояс ПК и финальную кнопку «Запланировать публикацию». Отдельную кнопку «Опубликовать» не нажимать, если проверяется только расписание.
3. Проверить сохранённое видео в Studio: совпали описание, дата, время, пояс и превью. Затем проверить пачку из двух видео, второе — после подтверждения первого. Проверить RU и EN, если используются оба интерфейса.
4. Если старый запуск уже создал видео, сначала проверить его ID/черновик в Studio. Не запускать повторную передачу файла вслепую: обновление календаря само по себе не превращает старую незавершённую загрузку в новое задание. Сначала сохранить/завершить существующий черновик вручную либо согласовать его удаление.

## Если появилась ошибка

- Дата не подтверждена: сверить ожидаемую дату с карточкой. Не нажимать произвольный день и не перезагружать мастер. В настройке предусмотрена остановка при неоднозначности.
- Время не найдено: сверить точное HH:mm. Не округлять до ближайших 15 минут. Приложить диагностический JSON: поле или карточка времени, видимые значения, язык интерфейса.
- Профиль открыт без CDP: не останавливать его автоматически. Сначала сохранить незавершённые действия, закрыть профиль вручную и повторить запуск через приложение. Не сбрасывать прокси и аккаунт.
- Ошибка после сохранения: сообщение содержит ожидаемые и прочитанные дату/время. Сначала проверить уже созданный ролик; повторная загрузка не исправляет часы.
- Диагностика сохраняется в подпапке `diagnostics` хранилища приложения. В JSON добавлены видимые элементы даты/времени, значения и `readOnly`; текст описания, cookies и токены туда не добавляются. Передать этот JSON и журнал, не весь профиль браузера.

## Автопроверки

`npm ci --prefix tools/uploader --ignore-scripts`, затем `node tests/browser/studio-schedule-chips.js` при установленном Chromium Playwright. Полный набор автоматически выполняет workflow ветки: 19 Node-регрессий, Windows-компиляция/сериализация/расписание, старые и новые Chromium-сценарии, проверка нативных окон.

Новый тест проверяет RU/EN: два видимых месяца и одинаковые числа, поле календаря с удалением из DOM после ввода, AM/PM-карточку и произвольное точное время 13:37 в редактируемом popup, асинхронное меню поясов, сохранённые описания двух последовательных роликов, отказ без угадывания, отсутствие перезагрузки мастера и реальное отключение CDP с сохранением страницы. Это локальные фикстуры без реальной публикации; проверка текущего Studio на ПК пользователя остаётся обязательной.
