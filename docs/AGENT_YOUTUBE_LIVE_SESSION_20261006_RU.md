# Эфиры через сохранённую сессию Dolphin — инструкция агенту

Новая ветка: `feature/youtube-live-dolphin-session-20261006`.
Основа: предыдущая реализация `feature/youtube-live-streams-20261005`, коммит `b069b6a98269e722c6f630caa3d82c49aa037d3f`.
Для установки этой версии используйте **эту инструкцию**. Предыдущая инструкция описывала создание новых эфиров через Google OAuth.

## Что изменилось

Новые эфиры создаются и управляются через существующий авторизованный браузер Dolphin. Google Cloud, OAuth JSON и разрешение Google приложению для новых эфиров не нужны. В окне запуска вместо OAuth — «Проверить сессию Dolphin». API-токен самого Dolphin по-прежнему нужен для подключения к его локальному API.

Программа подключается через CDP к правильному профилю, открывает собственную рабочую вкладку Studio, проверяет реальный `UC…` ID и выполняет действия в нативном интерфейсе. HTTPS-запросы к YouTube делает сам браузер с его cookies и прокси. Не используются придуманные внутренние live-endpoints и не экспортируются cookies в файлы. Интерфейс Studio может меняться: незнакомый или неоднозначный элемент приводит к ошибке, а не к нажатию первого попавшегося.

Это **автоматизированное управление обычной сессией**, а не гарантия неотличимости от человека. Сознательно не добавлены обход CAPTCHA, подмена браузерных признаков или обещание невидимости. Если Google требует вход/проверку, её выполняет владелец в Dolphin.

Важно разделять два соединения:

| Часть | Соединение |
|---|---|
| Управление Studio, метаданные, запуск/завершение | HTTPS из браузера Dolphin, его сессия и прокси |
| Видео из папки | FFmpeg → RTMPS по отдельному ключу эфира |
| Управление локальным Dolphin | HTTP/CDP только на 127.0.0.1 |

**Это не реализация «все байты по HTTPS» и не HLS.** RTMPS — отдельная защищённая передача видео. FFmpeg использует сеть ПК, не наследует браузерный прокси Dolphin. Если нужен прокси именно для видеопотока, это отдельная задача; не утверждайте, что он уже подключён.

## Поведение

- В существующем разделе YouTube отмечаются каналы. Окно: папка, название, описание, JPG/PNG-превью, теги, доступ, 720p/1080p, аудитория.
- Файлы только из выбранной папки сортируются по имени. Для порядка используйте `001.mp4`, `002.mp4`. Папка и параметры одинаковые для выбранных каналов.
- Всегда бесконечный цикл до остановки. Один FFmpeg-процесс на канал передаёт общий подготовленный плейлист; между повторами искусственных задержек нет. Подготовка файлов может занимать время/диск.
- Проверка сессии показывает настоящий канал. Подтвердите привязку строки к нему. Если Profile ID или порт Dolphin изменился — повторите проверку после завершения прежних эфиров. При завершении уже работающего эфира используется сохранённый порт.
- Событие сначала создаётся приватным с уникальным временным названием. Перед передачей применяются окончательные метаданные/доступ; название, описание, аудитория, теги и превью читаются обратно из Studio. При отсутствии подтверждения FFmpeg не запускается.
- Создаётся отдельный именованный ключ передачи. Не подменяется предыдущий ключ и не используется первый найденный эфир.
- Программа нажимает запуск только для собственного события после готовности Studio к приёму видео. Красный пульс появляется после подтверждённого состояния Studio, а не от существования процесса FFmpeg.
- Правый клик: завершить один канал. Общая кнопка завершает все эфиры программы. Остальные каналы продолжают работать при точечной остановке.
- Закрытие приложения сначала останавливает FFmpeg и запрашивает завершение в Studio. При аварийном выходе Windows Job Object останавливает принадлежащие приложению процессы FFmpeg/Node. Это прекращает передачу, но не гарантирует мгновенный переход YouTube в «Завершено» — журнал остаётся для проверки.
- Dolphin-профили и чужие вкладки не закрываются. Удаляется только рабочая вкладка этого worker. При невозможности подключения CDP профиль не перезапускается автоматически.
- Профиль, зарезервированный эфиром, блокируется для других workers приложения и команд закрытия профиля. Не переключайте вручную канал/Google-аккаунт и не закрывайте Dolphin-профиль во время эфира.
- При потере ответа создание события/ключа или нажатие запуска не повторяется автоматически. Неопределённое состояние сохраняется для завершения. Завершённая запись сохраняется; удаляется только собственное событие, которое не запускалось.

## Установка на ПК

1. Сохраните текущую установку/настройки. Работайте в отдельном checkout. Не делайте reset чужих незакоммиченных изменений.
2. Получите новую ветку:

```powershell
git fetch origin
git switch -c feature/youtube-live-dolphin-session-20261006 --track origin/feature/youtube-live-dolphin-session-20261006
```

Если ветка уже есть — `git switch feature/youtube-live-dolphin-session-20261006`, затем `git pull --ff-only`. При переносе в ветку с другими доработками изучите diff и merge/cherry-pick; не заменяйте целые файлы старой копией.

3. На Windows с .NET SDK и существующим полным runtime выполните через **Windows PowerShell**, не PowerShell 7:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\Build-YouTubeLiveSession-20261006.ps1 -RuntimeDirectory "C:\VideoBatch_Desktop" -OutputDirectory "C:\VideoBatch_Live_Session_Test"
```

OutputDirectory должен быть новой папкой. Скрипт собирает исходники, выполняет Node/C# проверки и настоящий FFmpeg-тест повторения, копирует новые workers с проверкой хешей. EXE из корня GitHub — старый; запускайте новый EXE из OutputDirectory. Артефакт Actions не содержит весь runtime и не является полноценным установщиком.

4. Убедитесь, что в новой папке есть `tools\uploader\worker-youtube-live-session.js`, новый `dolphin-session.js`, Node, Playwright, FFmpeg/FFprobe.
5. Запустите Dolphin, проверьте API-токен/порт в настройках программы. У каждой строки должен быть верный Profile ID. В каждом профиле владелец входит в нужный YouTube-канал. Live и пользовательские превью должны быть доступны каналу.
6. Отметьте каналы → «Запустить эфир» → в списке окна по очереди «Проверить сессию Dolphin» → подтвердите показанный `UC…` ID. Если ссылка содержит @handle вместо UC, особенно внимательно проверяйте реальный ID в подтверждении.
7. Выберите папку/параметры и для первого теста доступ **По ссылке**. Нажмите запуск.

## Обязательная проверка в настоящем Studio

CI/локальные fixtures **не подтверждают совместимость с текущим интерфейсом настоящего YouTube Studio**, аккаунтами, языком и прокси владельца. Эту часть нужно выполнить на ПК владельца. Поддерживаются текстовые элементы RU/EN; иной язык/новая разметка может потребовать адаптации по реально открытой странице.

1. Один тестовый канал, два коротких ролика: горизонтальный без аудио и вертикальный с аудио. Укажите название, описание, два тега и новое превью.
2. Проверьте правильный канал, приватное временное событие, отдельный ключ, сохранённые окончательные параметры и запуск.
3. Дождитесь двух полных повторов всей папки в зрительском проигрывателе. Убедитесь, что нет вставленных задержек между файлами/циклами.
4. Два канала: оба работают. Правым кликом остановите первый; второй продолжает. Затем общей кнопкой завершите второй. Проверьте Studio и отсутствие FFmpeg процессов.
5. Закройте приложение во время тестового эфира. Убедитесь, что передача остановилась и Studio подтвердил завершение. Аварийный выход проверяйте отдельно только на согласованном тестовом эфире; после перезапуска — «Проверить завершение», затем повторная остановка.
6. Проверьте неправильный канал, смену Profile ID, закрытый Dolphin, отозванную сессию, недоступный CDP, сетевой отказ во время создания/запуска/завершения. Не должно быть дублирующего события или ложного красного индикатора.
7. Во время эфира попробуйте другую задачу/закрытие того же профиля через приложение — должно быть явное сообщение о занятом профиле.

Если Studio изменил интерфейс: найдите этап по диагностике, изучите реальную рабочую вкладку и исправьте именно адаптер `NativeStudio`. Не добавляйте наугад URL/поля внутренних API, не отключайте проверку канала, не нажимайте первый эфир из списка. Не сохраняйте HTML, HAR, clipboard или скриншоты, содержащие cookies/ключи, в публичный репозиторий.

## Журнал, восстановление и совместимость

`%LocalAppData%\VideoBatchDesktop`:

- `youtube-live.xml`/`.bak`: привязки строк к профилям/каналам и незавершённые операции.
- `live-session\<operation>.json`: ID собственного события и подтверждённые этапы; без cookies/ключа передачи.
- `live-session\leases\<hash>.json`: резерв Dolphin-профиля. Сохраняется после сбоя до подтверждённого завершения.
- `live-session\<operation>.diagnostic.json`: команда, короткая безопасная ошибка, метод/path/HTTP-status последних запросов Studio. Без request body, query, headers, cookies и ключа.
- `youtube-live.log`: статусы приложения. `live-media` — временные подготовленные файлы.

Не удаляйте журнал/резерв, чтобы «разблокировать» повторный запуск, пока не проверены старые эфиры в Studio. Если событие не создавалось/уже вручную удалено и автоматическая проверка не может это подтвердить: сохраните резервную копию, проверьте точный канал/operation/ID в Studio, затем согласованно удалите только соответствующую запись XML и соответствующий lease. Другие операции не трогайте.

Старые OAuth-записи не переносятся незаметно на сессию. Незавершённый старый эфир сначала завершается прежним способом. Старый OAuth-адаптер оставлен для этого восстановления; новые эфиры из нового окна требуют сессию Dolphin. При смене способа привязка запрещена, если остался старый журнал.

Новые ключи остаются в Studio после завершения; ненужные ключи удаляются владельцем/агентом вручную после проверки завершения. Они не содержатся в локальном журнале. Старые media-папки после аварии можно удалить после завершения связанных эфиров.

## Что реально проверяют автоматические тесты

Node: неправильный канал, уникальность операций/резервов, неизвестный ID, отсутствие повторного создания после потери ответа, запрет запуска без метаданных, неопределённый запуск, очистка и отсутствие ключей в журнале.
C#: адаптер session→worker, привязка profile/channel/operation, управление несколькими каналами и точечная/общая остановка, восстановление, Windows Job Object, FFmpeg-повторы.
Отдельный Playwright-тест `tests/browser/youtube-live-studio-ui.js`: нативные элементы на **локальной подставной странице**, создание/метаданные/ключ/запуск/завершение. Настоящий Studio не имитируется как доказательство готового эфира.

После установки сообщите коммит и путь EXE, результаты автоматических проверок, ссылку настоящего тестового эфира, подтверждение повторов и обеих остановок, а также непроверенные случаи. Не выдавайте сборку или fixture за настоящий запуск на YouTube.
