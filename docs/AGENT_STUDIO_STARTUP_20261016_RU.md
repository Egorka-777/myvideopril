## Найденные причины и изменения

- `RenameVideoFile` в main ничего не переименовывал. Возвращено переименование исходного файла сразу при выборе в той же папке, без копирования. Коллизии получают свободное имя, существующий файл не перезаписывается. Ссылки на тот же исходник в остальных YouTube-каналах обновляются. Подтверждение замены пачки запрашивается до переименований.
- Перед публикацией `publicIp` открывал YouTube и сторонние IP-сервисы с несколькими длинными повторами. Для Studio этот путь исключён; открывается непосредственно Studio. Отдельная команда проверки IP сохранена.
- Старый запуск многократно ожидал API/подключение/навигацию. Для Studio: авторизация локального API — 8 секунд, запрос запуска — одна попытка до 20 секунд, CDP — до 20 секунд, новая вкладка — 15 секунд. При отказе выводится ошибка этапа, профиль не перезапускается.
- Подключение Playwright к Chromium может зависнуть на существующей не отвечающей вкладке. Это воспроизведено в отдельном тесте. Новый предел ожидания освобождает подключение; он не является ремонтом сетевого соединения или произвольной зависшей вкладки пользователя.
- Передача небольших файлов идёт через штатный Playwright input. Большие файлы передаются через CDP с поиском помеченного input внутри Shadow DOM. Старый поиск `DOM.querySelector(document)` не проходил сквозь Shadow DOM. Неопределённо завершившаяся передача не повторяется автоматически.
- Заголовок и описание вводятся до ожидания ID ролика. ID мог появляться позже и блокировал весь экран с первоначальным названием файла.
- Выбирается видимый активный диалог, включая `ytcp-video-upload-dialog`; скрытые старые окна игнорируются. Переключатель «Развернуть / Show more» ищется по стабильному ID, ожидается появление настроек рекламы и изменённого контента. Ответы берутся из сохранённых настроек приложения; настройки должны соответствовать фактическому содержимому ролика.
- Для расписания выбирается и проверяется часовой пояс ПК в Studio. Emulation timezone самого Dolphin-профиля больше не меняется.
- Контрольная отметка `StudioPending` сохраняется непосредственно перед передачей файла. Ошибка открытия Studio до передачи не блокирует новый файл. При неопределённом результате после передачи защита от дублей остаётся. Диагностика и отключение CDP ограничены по времени.

## Проверка на пользовательском ПК

Не утверждать, что причиной была нагрузка, без замеров. Не менять прокси, профиль, реестр или параметры ОС наугад.

- Проверить сначала один выбранный профиль и одно разрешённое пользователем тестовое видео. Убедиться, что в исходной папке имя поменялось уже при выборе файла, а число файлов не увеличилось.
- Сопоставить журнал приложения с открытым окном: запрос Dolphin → CDP → Studio → выбор файла → перепечатка названия → «Развернуть» → реклама/ИИ → расписание → проверка сохранения.
- После успешной проверки одного профиля проверить выбранную пользователем параллельность на нескольких профилях. При повторном зависании сохранить точный этап и длительность, версии Dolphin/Chromium, загрузку CPU/RAM/диска, количество вкладок и локальную доступность `/json/version`. Не включать в отчёт токены, cookies, пароли и исходные session-файлы.
- Если остался `StudioPending` от прежней попытки, сначала вручную проверить черновики/контент в Studio по `StudioVideoId` и заголовку. Не сбрасывать защиту и не отправлять файл заново вслепую.

Реальный Dolphin, пользовательские прокси и публикации на его каналах в изолированных тестах не проверяются. Их результат нужно подтвердить на ПК; автоматические просмотры/лайки этой доработкой не менялись.
