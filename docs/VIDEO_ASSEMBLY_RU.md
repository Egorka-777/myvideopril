# Сборка роликов: как открыть и пользоваться

Новая функция находится в меню **Контент → Сборка роликов**. Здесь и настраивается шаблон — в самом приложении, без CapCut и ручного редактирования кода.

## Запуск готового комплекта

В GitHub Actions открой успешный запуск **Video assembly Windows kit**, скачай artifact **VideoBatch-Assembly-Windows**. Внутри скачанного архива находится **VideoBatch-Assembly-Windows.zip**. Извлеки его полностью в отдельную папку, например `C:\VideoBatch-Assembly`. Запусти `VideoBatch.exe`. В комплекте находятся FFmpeg, FFprobe, Node и загрузчики. Не запускай EXE прямо из архива. Сначала закрой предыдущую копию VideoBatch: у приложения сохраняется защита от одновременного запуска двух окон.

Windows 10/11, .NET Framework 4.8. Сборка в этой ветке также включает предыдущую доработку обработки `feat/processing-ranges-effects-20261005`. Основная ветка не меняется.

## Структура по последнему уточнению

| Сцена | Фон | Что накладывается |
|---|---|---|
| 1. Hook | Начальное видео из «Видео» | Готовая картинка из «Заголовки» |
| 2. Торговля | Видео из «Торговля» | Готовая картинка из «Заголовки-2» |
| 3. TG-бот и призыв | Другое видео из «Видео» | Постоянный скриншот из «TG-бот» и картинка из «Призыв» |

Первый и второй заголовки — именно изображения, которые пользователь добавляет сам. Скриншот бота не генерируется и не заменяется: режим «Постоянное изображение» берёт первый файл по имени. Оставь в этой папке один нужный скриншот. Финальный призыв может выбираться из нескольких картинок; для одного постоянного призыва оставь одну картинку или включи «Постоянное изображение».

Начальные длительности: **5 + 6 + 6 = 17 секунд**. Это редактируемый пример, а не ограничение: можно задать другие длительности или добавить сцены. Переход по умолчанию — плавный, 0,35 секунды. Для первых двух сцен требуются исходники не короче 5,35 и 6,35 секунды; для последней — не короче 6 секунд. Проще подготовить исходники от 7 секунд. Программа выбирает внутри длинного видео участок нужной длины. Оригинальный звук видеокусков не используется; музыка идёт одной дорожкой через весь ролик.

## 1. Добавить материалы

1. Открой вкладку **1. Материалы**. По умолчанию папка `Материалы-сборки` находится рядом с EXE. Для установки в защищённую папку, например Program Files, выбери другую доступную для записи папку.
2. Нажми **Создать папки**. Откроется папка материалов с подпапками `Видео`, `Торговля`, `Заголовки`, `Заголовки-2`, `TG-бот`, `Призыв`.
3. Скопируй файлы в соответствующие подпапки. Либо выбери строку материала в приложении и нажми **Добавить файлы** / перетащи файлы на эту строку. Приложение копирует файлы и сохраняет оригиналы.
4. Укажи музыку и папку готовых роликов. Музыка необязательна; короткий трек повторяется до конца ролика. Для непрерывного неповторяющегося музыкального фрагмента выбирай трек длиннее ролика.

Видео: MP4, MOV, MKV, AVI, WEBM, M4V. Изображения: PNG, JPG/JPEG, BMP, GIF (статичная картинка, без анимации). Прозрачность PNG сохраняется. Для аккуратных заголовков со скруглённой чёрной плашкой подготовь PNG с прозрачным фоном вокруг плашки. Приложение вписывает картинку в указанную область без растягивания и обрезки. Дополнительно поддерживаются UTF-8 TXT: из такого файла программа сама рисует белый жирный текст на чёрной скруглённой плашке.

## 2. Настроить расположение прямо в приложении

1. Перейди на **2. Шаблон и расположение**.
2. Выбери сцену в верхнем списке. Укажи её длительность и папку видео. Пустая папка видео означает общую папку `Видео`.
3. В следующем списке выбери изображение. Источник может быть папкой с вариантами или одним конкретным файлом. Кнопка **Выбрать один файл изображения** подходит для постоянного скриншота бота.
4. Нажми **Показать кадр**, чтобы увидеть реальный фоновый кадр и картинки. Перетаскивай зелёную рамку мышью. Нижний правый угол рамки изменяет её размер. Положение и размер также задаются числами в процентах кадра.
5. Укажи время появления и исчезновения изображения внутри сцены. Значение исчезновения `0` означает до конца сцены. Нижнее изображение в списке накладывается поверх верхнего.
6. **+ Изображение** добавляет ещё один слой, **− Изображение** убирает слой.

Зелёные рамки и имена слоёв — только элементы редактора, в готовом видео их нет. Статичный кадр показывает расположение; время появления, движение видео, переходы и звук проверяются кнопкой **Собрать пример**. После выбора другой сцены нажми «Показать кадр» для её фона.

## 3. Добавить сцену в любой промежуток

Выбери существующую сцену и нажми **+ Перед** или **+ После**. Новая сцена сразу вставится в выбранный промежуток. Приложение создаст отдельную папку `Материалы-сборки\Сцены\Сцена-xxxxxx`, а внутри — **Видео** и **Изображения**. Эти пути сразу назначены новой сцене. Добавь туда материалы, настрой наложение и длительность. Стрелки **↑ / ↓** меняют порядок сцен. Добавлять можно от 2 до 12 сцен, до 8 изображений в каждой. Удаление сцены из шаблона не удаляет файлы материалов.

## 4. Собрать пример и партию

На вкладке **3. Сборка** выбери число роликов, формат, переход и громкость. Доступны обычная склейка (`cut`), плавный переход (`fade`), через чёрный/белый, сдвиги, плавное смещение, размытие и приближение. Они реализованы через FFmpeg и не являются импортом фирменных эффектов CapCut.

Нажми **Собрать пример**: создастся MP4, откроется в видеоплеере Windows. Пример не расходует заголовки и не добавляется в историю партии. После проверки нажми **Собрать ролики**. Кнопка **Стоп** отменяет работу; уже успешно созданные файлы остаются, текущая незавершённая сборка удаляется. Для каждого успешного ролика рядом сохраняется `.assembly.xml` — точный список использованных материалов и выбранных участков видео.

## Повторы и сохранение

- Для первых двух заголовков по умолчанию включено **Не повторять в следующих роликах**. Из 10 первых и 10 вторых заголовков получится максимум 10 роликов без повторения заголовков. Переименованные копии с тем же содержимым не добавляют вариантов.
- У постоянного скриншота бота эта отметка выключена. Призыв по умолчанию допускает повторение; можно включить запрет повторов отдельно.
- Видео повторно используются между разными роликами. Внутри одного ролика один и тот же видеофайл не используется дважды. Полностью одинаковая последовательность видео и изображений не выпускается снова в истории этого шаблона.
- Если материалы без повторов закончились, программа выдаёт доступное число роликов и сообщает причину. Не подставляет уже использованный заголовок.
- Шаблон сохраняется кнопкой **Сохранить шаблон** и при закрытии окна. **Экспорт шаблона** сохраняет отдельный XML, **Загрузить шаблон** открывает ранее экспортированный.
- Шаблон и история находятся в каталоге настроек VideoBatch: `assembly-template.xml` и `assembly-history`. Загрузка того же шаблона сохраняет его ID и историю, даже если изменена папка результатов. Обычный `settings.xml` и аккаунты не переписываются новым режимом.

## Для агента / разработчика

Изолированная ветка: `feat/template-video-assembly-20261006`. База: `e6de932500fcb3431ef98cab14fe98e99f7a9457` из ветки обработки. Код: `AssemblyTemplate.cs` (модель, пулы, история, планирование), `AssemblyWindow.cs` (окно и перетаскивание), `AssemblyRaster.cs` (прозрачные слои и текстовые плашки), `AssemblyEngine.cs` (сцены, переходы, музыка, проверка MP4). Вызов подключён через `AppShell.cs` и `NavigationService.cs`.

Сборка: `dotnet build VideoBatch.csproj -c Release -p:ApplicationIcon=`. Windows-тесты: `AssemblyRegressionTests.RunPlannerTests`, `RunRasterTests`, `RunUiTests`, а также прежние тесты обработки. Реальное видео: `dotnet build tests/AssemblyHost/AssemblyHost.csproj -c Release`, затем `python tests/assembly_integration.py --host tests/AssemblyHost/bin/Release/net8.0/AssemblyHost.dll`.

`--portable` в интеграционном тесте предназначен для Linux: PNG уже нарисованы размером с кадр, проверяется производственный планировщик и FFmpeg-сборщик; Windows-рендер изображений и WinForms проверяются отдельно на Windows. GitHub Actions выполняет Windows-проверки и после успеха создаёт готовый комплект. При ошибке фильтра не объявлять сборку успешной и не отключать проверки. На ПК пользователя сначала собрать один пример из его реальных материалов и просмотреть его перед массовым экспортом.
