## 3. Обязательные правила совместимости

1. Новая кнопка в «Обработка видео»: **«Фильтры и эффекты»**. Она открывает четыре вкладки: «Фильтры», «Аудио», «Видеоэффекты», «Метаданные».
2. Все новые галочки выключены по умолчанию. Старый `settings.xml` без раздела `Processing` получает выключенные дополнения. Прежние диапазоны, профили вариантов, музыка и аккаунты не сбрасываются.
3. Когда все дополнения выключены, используется прежняя цепочка обработки. Не включать эффекты при установке автоматически.
4. Общая панель действует и на короткие, и на длинные видео. Значения выбираются заново **для каждого исходного файла и каждого варианта**.
5. Равные «от» и «до» означают фиксированное значение. «От» больше «до», NaN, бесконечность и выход за пределы отклоняются. Не исправлять это тихой перестановкой значений.
6. Включённые обрезка, скорость, яркость и контраст заменяют соответствующее значение старой обработки. Выключенные сохраняют прежние значения.
7. Громкость — множитель уже настроенного звука: 100% сохраняет текущую громкость; 50% уменьшает вдвое. Прежняя громкость фоновой музыки сохраняется отдельно.
8. Тон, темп и дополнительная громкость действуют на итоговое аудио, включая исходник, музыку и озвучку. Исходник и озвучка подрезаются вместе с видео; фоновая музыка подбирается под результат.
9. Подрезка задаётся **суммарным** процентом длительности, не процентом с каждой стороны. После неё скорость меняет оставшуюся длину. Пример: 4 секунды, 15% подрезки, 125% скорости → `4 × 0.85 / 1.25 = 2.72` секунды (с небольшой погрешностью кадра/аудиопакета).
10. Тон компенсируется по темпу. Отдельный темп не меняет длину видео: избыток аудио обрезается, недостаток дополняется тишиной. При ускорении аудио тишина в конце допустима и объяснена в панели.
11. Fade In / Out ограничиваются половиной итоговой длины каждый. Поворот сохраняет разрешение; свободные края чёрные. Не выдавать это за ошибку или добавлять незаявленный автоматический кроп.
12. «Случайные настройки» меняет диапазоны **уже включённых** параметров внутри мягких значений. Старые настройки и галочки включения не меняет. Для самого рендера эта кнопка не нужна: случайный выбор уже происходит автоматически.
13. Пресет содержит только эту новую панель. Импорт не заменяет аккаунты, настройки загрузок, токены, старые профили и музыкальные списки. Отмена диалога не применяет изменения.
14. Model и Software — связанные шаблоны выбранного бренда, записываемые в теги `make`, `model`, `software`. Они не являются доказательством, что видео снято данным устройством, и не имитируют полный аппаратный EXIF.
15. Дата при включении выбирается из последних N суток. Будущих дат нет. При выключенной рандомизации времени сохраняется текущее время суток и случайно выбирается целое число дней назад. N=0 означает текущий момент. Дата пишется в метаданные и даты нового файла.
16. Обработка не перезаписывает исходники. Ошибка и «Стоп» удаляют незавершённый результат. Успех подтверждается реально созданным файлом.

## 4. Сначала сохранить работающую установку

1. Определи реальный путь: `Get-Process VideoBatch -ErrorAction SilentlyContinue | Select-Object Id,Path`. Запиши путь старого EXE и его ярлыка.
2. Если приложение выполняет задания, дождись их завершения. Не отменяй чужую текущую загрузку ради установки.
3. Штатно закрой только VideoBatch. Dolphin и его профили не закрывай. Не убивай процессы принудительно.
4. Сделай копию **всей** `%LOCALAPPDATA%\VideoBatchDesktop` в отдельную папку с датой/временем. Проверь копию `settings.xml`, если исходный файл существует. Токены в XML защищены Windows; не расшифровывай их и не публикуй настройки.
5. Старую папку установки не изменяй. Сохрани старый ярлык. Новая версия устанавливается в отдельную папку.
6. Обе версии используют общие настройки: не запускать одновременно. Новые включённые параметры старая версия не умеет сохранять, поэтому перед возвращением к ней сохрани актуальную копию XML отдельно.

## 5. Получить именно эту ветку

В отдельной папке:

```powershell
git clone --branch feat/processing-ranges-effects-20261005 https://github.com/Egorka-777/myvideopril.git VideoBatch-processing-20261005
Set-Location VideoBatch-processing-20261005
git status --short
git rev-parse HEAD
```

При существующем клоне сначала проверь локальные правки. Используй отдельный worktree:

```powershell
git status --short
git fetch origin
git worktree add --detach ..\VideoBatch-processing-20261005 origin/feat/processing-ranges-effects-20261005
Set-Location ..\VideoBatch-processing-20261005
git rev-parse HEAD
```

Если имя папки занято, выбери новое. Не удаляй существующую папку, не делай `reset --hard`. Не использовать `main` или инструкции старых веток как замену этому документу.

## 6. Сборка и тесты на ПК

Нужны .NET Framework 4.8, .NET SDK/runtime 8 и Python 3. Зависимости теста обработки — стандартная библиотека Python, NumPy не требуется. Не заменять Node/FFmpeg в старой установке.

Найди runtime старого комплекта: `tools\uploader\node.exe`, `tools\uploader\node_modules\playwright-core`, `tools\ffmpeg.exe`, `tools\ffprobe.exe`.

Запускай новый скрипт через **Windows PowerShell `powershell.exe`**, не `pwsh`. Подставь действительные пути вместо `<...>`:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\Build-Processing-20261005.ps1 -RuntimeDirectory "<старая рабочая папка>" -OutputDirectory "<новая ещё не существующая папка>" -Python "<путь к python.exe>"
```

Скрипт:

1. Запускает прежние Node regressions.
2. Собирает весь EXE и выполняет C# `RunAll`, включая новые проверки диапазонов, XML, пресетов и создания интерфейса.
3. Копирует полный runtime и все workers текущей ветки, сверяет JS-хэши.
4. Собирает тестовый .NET 8 host против **того EXE, который попал в новый комплект**.
5. Запускает `tests/processing_integration.py` с настоящими FFmpeg/FFprobe **старого рабочего runtime**. Тест измеряет длительности, частоту/громкость аудио, изменения пикселей и фактически сохранённые метаданные. Тестовые файлы создаются во временной папке, не в папках пользователя.
6. Добавляет эту инструкцию, `START_HERE.txt`, `SOURCE_COMMIT.txt`, обновляет `SHA256_MANIFEST.txt`.

Проверяй код завершения после каждой вручную выполненной команды. Если тест не прошёл, новый комплект не запускай как готовый. Установи причину. Если FFmpeg не поддерживает фильтр, сохрани его версию и точное сообщение; не выключай этот тест и не объявляй успех. Старый runtime не перезаписывай: совместимую версию можно готовить только в новом комплекте и повторять проверки.

Дополнительно выполнить прежние браузерные проверки из `docs/AGENT_PROFILE_STABILITY_20261005_RU.md`: они проверяют, что предыдущая работа с профилями сохранилась.

## 7. Проверка интерфейса и результата на ПК

Используй копии тестовых роликов, не оригиналы рабочих файлов. Не загружай результаты на платформы и не запускай публикации ради этого задания.

1. Запусти новый EXE. Проверь аккаунты, исходные диапазоны, музыку, фон, папку результата и количество вариантов. Сверь с сохранёнными настройками. Новые эффекты выключены.
2. Открой «Обработка видео» → «Фильтры и эффекты». Проверь все четыре вкладки, все параметры из таблицы выше, доступность полей при включении/выключении и прокрутку при масштабе Windows пользователя.
3. Сначала обработай тестовый файл с выключенными дополнениями. Результат должен соответствовать старому режиму.
4. Затем отдельно проверь подрезку, поворот, скорость, яркость/контраст, резкость и шум. Не включать всё разом при поиске дефекта: иначе нельзя установить, какой параметр не работает.
5. Для скорости/подрезки проверь длительность и синхронизацию звука. Для громкости проверь 0 / 50 / 100%; для тона и темпа — отдельно, затем вместе. Не сравнивай только текст команды FFmpeg: послушай/посмотри готовый файл и сверь FFprobe.
6. Проверь Fade In и Out в начале/конце, горизонтальное отражение, сетку, движение зума, всплески громкости. Проверь короткий ролик, чтобы длинный fade не ломал результат.
7. Отдельно протестируй Shorts с музыкой, Long с исходным аудио, Long с фоном и озвучкой, вертикальный ролик без аудио. Существующая логика озвучки/музыки должна сохраняться.
8. Создай несколько вариантов одного файла с ненулевыми диапазонами. Повтори с другим исходником: выбор значений происходит снова. Не обещай различия, если все диапазоны зафиксированы и включены только постоянные эффекты.
9. В метаданных оставь один бренд, например OnePlus. «Прокрутить пример» и готовые файлы должны содержать только его связанные шаблоны. Проверь сохранение выбора после закрытия диалога и перезапуска приложения.
10. Включи запись даты на 30 дней, затем 0 дней. Проверь UTC `creation_time` через FFprobe и локальное отображение дат файла; учитывать часовой пояс. Будущих дат быть не должно.
11. Сохрани пресет, поменяй диапазон, загрузи пресет: значения возвращаются, аккаунты и музыка не меняются. Неверный диапазон и отсутствие разрешённых брендов при включённой записи вызывают понятную ошибку. Не заменяют исходные настройки.
12. Измени диапазон → «Сохранить» → закрой окно обработки → открой снова → перезапусти VideoBatch. Значение сохраняется. Проверка важна: окна теперь используют один объект настроек, без старого перезаписывания копией.
13. Измени поле и нажми «Отмена»: изменение не применяется. Нажми «Выключить всё» и сохрани: прежняя обработка снова активна.
14. Нажми «Стоп» во время создания вариантов. Дождись окончания. Исходник остаётся неизменным, `.processing_*` незавершённые файлы удалены. Ошибка одного файла не выдаётся за успех.
15. Проверь прежнее сохранение открытого профиля и меню удаления на безопасном тестовом аккаунте по предыдущей инструкции. Не удаляй рабочие аккаунты и не публикуй лишние ролики.

## 8. Установка и возврат

После успешной проверки создай **отдельный новый ярлык**, например «VideoBatch — обработка 05.10». Проверь его фактический путь. Старый EXE и ярлык сохранить.

При дефекте заверши задания новой версии, штатно закрой её, сохрани свежую копию настроек и диагностику. Старую версию запускать отдельно. Не восстанавливай резервный XML автоматически: это может отменить удаления аккаунтов, настройки и очереди, изменённые после копирования. Восстановление настроек — только по конкретному согласованному решению пользователя.

## 9. Итоговый отчёт
