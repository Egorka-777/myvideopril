# Прямые эфиры YouTube: установка и проверка

Ветка: `feature/youtube-live-streams-20261005`.
Основа: `fix/profile-stability-account-delete-20261005`, коммит `6bd303cdf1cef6df69d3df643e66d4a55cdeafd5`.

## Что сделано

- В существующем разделе YouTube добавлена кнопка «Запустить эфир».
- Используются галочки текущего списка каналов. Другие каналы не запускаются.
- Окно запуска: папка, название, описание, JPG/PNG-превью, теги через запятую, доступ, качество 720p/1080p, аудитория.
- Одна папка и одни параметры применяются ко всем отмеченным каналам. Подпапки не включаются.
- Видео сортируются по имени файла без учёта регистра. Для порядка используйте `001.mp4`, `002.mp4` и т. д.
- Папка всегда проигрывается бесконечно по кругу. Однократного режима нет. Между файлами и повторениями не вставляются задержки; один FFmpeg-процесс передаёт весь плейлист.
- Приложение заранее приводит файлы к одинаковому формату: H.264, AAC, 30 fps, стерео 48 kHz, 720p/1080p. Видео без звука получает пустую звуковую дорожку. Пропорции сохраняются с полями.
- Подготовка общая для пачки каналов, а передача каждому каналу идёт отдельным процессом без повторного кодирования. Перед первым запуском может потребоваться время и место на диске для подготовки.
- Красный пульсирующий кружок и статус «В эфире» появляются только после `lifeCycleStatus=live` и `streamStatus=active` от YouTube.
- При отсутствии подтверждения отображается проверка связи, а не фиктивное «В эфире».
- Правый клик: завершить эфир этого канала, завершить все, открыть страницу эфира, подключить API.
- Общая кнопка меняется на «Завершить все эфиры», если есть работающие/запускающиеся/незавершённые эфиры. Для запуска дополнительных каналов используйте «Ещё → Запустить эфир на отмеченных каналах».
- Остановка одного канала не останавливает остальные. Общая остановка затрагивает все эфиры, запущенные этой программой, включая скрытые текущим фильтром; чужие эфиры не затрагиваются.
- Закрытие приложения сначала останавливает передачу и завершает эфиры. При недоступности YouTube показывает проблему и сохраняет сведения для повторного завершения.
- Удаление аккаунта из YouTube или общей панели профилей блокируется, пока его эфир не завершён подтверждённо.

## Важная первоначальная настройка

Вход в Dolphin не является OAuth-разрешением на YouTube API. Для этой реализации нужно один раз подключить каждый YouTube-канал. После подключения программа использует защищённый refresh token и не требует открытия всех профилей для каждого запуска. Повторное разрешение потребуется при отзыве/истечении доступа.

Авторизация открывается в системном браузере. Выберите именно нужный Google-аккаунт и YouTube-канал; наличие готовой сессии Dolphin не подменяет выбор OAuth-канала. Перед привязкой приложение показывает реальное название и ID, а при известной ссылке `/channel/UC…` или `@handle` проверяет совпадение.

1. В Google Cloud создайте/выберите свой проект.
2. Включите **YouTube Data API v3**.
3. Настройте Google Auth Platform / экран согласия. Для режима Testing добавьте Google-аккаунты владельцев каналов в Test users. Для рабочего использования учитывайте требования Google к публикации/проверке приложения.
4. Создайте OAuth client типа **Desktop app**, скачайте JSON. Web application JSON не подходит.
5. В приложении отметьте каналы → «Запустить эфир» → «Импорт OAuth JSON».
6. Выберите первую строку в списке окна → «Подключить выбранный канал». В браузере предоставьте доступ, проверьте название/ID в подтверждении.
7. Повторите для остальных выбранных каналов. Один реальный канал нельзя запускать одновременно через две разные локальные строки.
8. Каждый канал должен иметь доступ к прямым эфирам в YouTube Studio. Программа не снимает ограничения YouTube и не включает недоступную функцию автоматически.

В режиме Testing Google может выдавать refresh token сроком на 7 дней для этих разрешений. Не объясняйте повторный запрос доступа «сломанным Dolphin»: проверьте статус OAuth и сроки токенов.

OAuth client secret и refresh tokens хранятся через Windows DPAPI CurrentUser. Не переносите `youtube-live.xml` как работающие настройки на другого пользователя Windows: потребуется переподключение.

## Получение и сборка — по шагам

Работайте в отдельном checkout, сохранив текущую установленную программу и настройки. Не сбрасывайте чужие незакоммиченные изменения и не перезаписывайте другие ветки.

```powershell
git fetch origin
git switch -c feature/youtube-live-streams-20261005 --track origin/feature/youtube-live-streams-20261005
```

Если локальная ветка уже существует, переключитесь на неё и выполните `git pull --ff-only`. Если агент работает в другой ветке с новыми правками, изучите расхождения и перенесите изменения через merge/cherry-pick, разрешив конфликты осмысленно. Не заменяйте весь `YouTubeWorkspacePanel.cs` старой копией.

Нужны Windows, .NET SDK с возможностью сборки net48 и существующая полная установка VideoBatch с Node, Playwright, FFmpeg и FFprobe. Используйте **Windows PowerShell `powershell.exe`**, не `pwsh`, для запуска reflection-тестов .NET Framework.

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\Build-YouTubeLive-20261005.ps1 -RuntimeDirectory "C:\VideoBatch_Desktop" -OutputDirectory "C:\VideoBatch_Live_Test"
```

`RuntimeDirectory` — существующая полная установка. `OutputDirectory` — новая, ещё не существующая папка. Скрипт:

1. Запускает существующие Node-регрессии и C# self-tests.
2. Собирает текущие исходники, не использует старый EXE из корня репозитория.
3. Копирует актуальные workers и зависимости из проверенных источников.
4. Выполняет новые проверки жизненного цикла/API на подставных ответах.
5. На настоящем FFmpeg проверяет разные форматы, отсутствие аудио, повторение плейлиста и временные метки.
6. Создаёт инструкцию, SOURCE_COMMIT и SHA256_MANIFEST.

Старый `VideoBatch.exe` в корне GitHub не содержит новую функцию. Запускайте EXE из новой собранной папки. Артефакт GitHub Actions тоже требует штатного runtime; это не установщик с FFmpeg/Node.

## Реальная проверка на YouTube

Автоматические тесты не подтверждают настоящий эфир. Финальную проверку агент выполняет на ПК владельца и его каналах. Для первого запуска выберите доступ **По ссылке**. Не публикуйте публичные тестовые эфиры без указания пользователя.

1. Подключите один тестовый канал к API. Выберите папку с двумя короткими видео разных форматов: одно без аудио, другое с аудио. Укажите понятное название, два тега и JPG/PNG-превью.
2. Нажмите запуск. Проверьте статус подготовки, затем запуска. Откройте ссылку эфира и YouTube Studio.
3. Убедитесь: совпадают канал, название, теги и обложка; зритель видит видео со звуком там, где он есть. Дождитесь не менее двух полных повторов папки. Не должно быть намеренных остановок между файлами/повторами.
4. Включите два канала. Оба должны показывать видео, красные индикаторы появляются после ответа API.
5. Правым кликом завершите первый. В Studio первый эфир завершается, второй продолжает передачу и повторение.
6. Общей кнопкой завершите все. Проверьте завершение в Studio, остановку FFmpeg и очистку временных media-файлов.
7. Повторное нажатие не должно создавать дубли. Включите фильтр/смените RU/EN и убедитесь, что общая остановка завершается для всех запущенных этой программой каналов.
8. Закройте приложение во время эфира. Оно должно сначала остановить/завершить эфиры. Если YouTube недоступен, проблема должна быть видна, а сведения — сохранены.
9. Аварийное завершение проверяйте только на согласованном тестовом эфире. После перезапуска должен появиться статус «Проверить завершение». Повторите остановку; не запускайте новый эфир до подтверждённого завершения прежнего.
10. Проверьте пустую папку, битый файл, слишком большую обложку, неправильный канал, отозванный OAuth, ограничения live/thumbnail, отсутствие FFmpeg, отказ сети во время создания и остановки. Не объявляйте успешным сценарий, который реально не проверен.

## Архитектура и диагностика

`YouTubeWorkspacePanel` + partial `.Live.cs` → `YouTubeLiveDialog` → `YouTubeLiveManager` → `YouTubeLiveApi` + `YouTubeLiveMedia/LiveEncoder`.

Официальные операции:

- OAuth Desktop: authorization code + PKCE + случайный state + loopback 127.0.0.1; offline token refresh.
- `channels.list(mine=true)` проверяет авторизованный канал; `forHandle` — известный @handle.
- `liveBroadcasts.insert` создаёт событие с автостартом/автостопом и аудиторией.
- `liveStreams.insert` создаёт отдельный поток для канала.
- `liveBroadcasts.bind` связывает событие и поток.
- `videos.list/update` задают название/описание/теги, сохраняя обязательную categoryId.
- `thumbnails.set` загружает выбранную обложку до начала передачи.
- Передача: RTMPS, FFmpeg, плейлист, `-stream_loop -1`, H.264/AAC без перекодирования во время передачи.
- `liveBroadcasts.list` и `liveStreams.list` подтверждают состояние.
- `liveBroadcasts.transition(complete)` завершает эфир; не стартовавшее событие удаляется. Запись завершённого эфира сохраняется.

Создание не повторяется автоматически при потере ответа: оно уже могло выполниться. До запроса сохраняется уникальная операция, а после каждого создания — ID. Если ответ потерян, завершение ищет созданные ресурсы по уникальному маркеру. В публичном описании маркер удаляется при установке окончательных метаданных до передачи видео.

Во время передачи есть ограниченные перезапуски FFmpeg (до 3) в тот же эфир. Это не гарантия продолжения при любом обрыве: YouTube может завершить эфир, сеть может отсутствовать, квота/разрешение может закончиться. Ошибка показывается, новый эфир автоматически не создаётся.

Файлы в `%LocalAppData%\VideoBatchDesktop`:

- `youtube-live.xml` + `.bak`: конфигурация, защищённые tokens, незавершённые операции.
- `youtube-live.log`: события и ошибки без OAuth tokens и ключа передачи.
- `live-media\<operation>`: временные подготовленные файлы; нормальная остановка очищает свою папку. После аварии старые media-папки можно удалить вручную только после завершения связанных эфиров.

Прокси Dolphin применяется к браузеру Dolphin. В этой реализации API и RTMPS используют соединение ПК; настройки прокси Dolphin не перенаправляют FFmpeg. Это нужно учитывать при оценке сети.

720p использует примерно 4 Мбит/с видео + 0,128 Мбит/с аудио на канал; 1080p — 6 + 0,128. Пример 10 каналов 720p: `10 × (4 + 0,128) = 41,28 Мбит/с` отдачи до накладных расходов. Нужен запас пропускной способности. Точное число каналов на конкретном ПК подтверждается измерениями.
