# Обновление YouTube Studio: загрузка → расписание → публикация → комментарий автора

Ветка: `feat/studio-publish-workflow-20261021`.
Маркер в журнале worker: **`2026-10-21-studio-publish-v5`**.
Включены ранее проверенные исправления Studio (`5d8b1fc`) и Telegram Web / шаблоны профиля (`f0e464e`). Их ещё нет в `main` на момент подготовки этой ветки. Telegram worker остаётся `2026-10-19-telegram-profile-v6`.

## Установка на ПК

1. Остановить задания и закрыть VideoBatch. Сохранить резервную копию текущего EXE, `tools/uploader`, `tools/telegram` и папки настроек, путь к которой показан в приложении. Не удалять настройки, Telegram vault, импортированные сессии, WebView-профили или прокси.
2. На GitHub открыть Actions → **YouTube Studio RU EN upload**, выбрать успешный запуск именно этой ветки. Скачать **VideoBatch-Studio-Publish-Update**. Убедиться, что `SOURCE_COMMIT.txt` соответствует проверенному запуску.
3. Заменить EXE, DLL / `runtimes` и приложенные исходники `tools/uploader`, `tools/telegram` в действующей установке. Сохранить имеющиеся `node.exe` и `tools/telegram/python`. Не заменять EXE файлом из старого архива `main`.
4. В каталоге приложения выполнить `npm ci --prefix tools/uploader --ignore-scripts` имеющимся Node / npm. Если npm не в PATH, использовать установленный комплект Node на ПК; не копировать чужой `node_modules`.
5. Запустить приложение. В журнале первого задания проверить новый маркер. Если маркер старый, проверить путь запущенного EXE и путь worker; повторные переустановки аккаунтов не помогут.

Если сборка из исходников: `git fetch origin`, создать отдельную локальную ветку от `origin/feat/studio-publish-workflow-20261021`, собрать `dotnet build VideoBatch.csproj -c Release`. При наличии местных изменений сначала сохранить их коммитом/отдельной веткой и объединить; не использовать `reset --hard` и не затирать пользовательскую установку. Ветка уже включает предыдущие Telegram-исправления, отдельный старый EXE не нужен.

## Как пользоваться

**Загрузка.** Отметить аккаунты ✓ → добавить видео и превью → «Через Studio». Имя файла меняется в исходной папке по существующей логике приложения. В Studio заголовок очищается клавишами и вводится заново. Описание и теги из сохранённых настроек Studio не заменяются общей базой приложения. Значения рекламы / изменённого контента берутся из уже существующих настроек приложения и должны соответствовать ролику.

Длинные видео: завершение передачи файла → превью → шаги мастера → «Доступ / Visibility» → карточка «Запланировать публикацию / Schedule» → дата, время и пояс ПК → финальная кнопка планирования → проверка сохранённого расписания и превью. На экране «Доступ» больше не ищется «Далее». Shorts сохраняют существующий режим немедленной публикации.

**Текст автора.** Правая кнопка по аккаунту → «Комментарий автора…». Для каждого аккаунта свой шаблон. Например, нейтральный шаблон: `Материалы к ролику: https://example.com/?date={ddMM}`. Приложение заменяет только явные вставки:

| Вставка | Пример для 21.10.2026 |
| --- | --- |
| `{ddMM}` | `2110` |
| `{date}` | `2026-10-21` |
| `{dd}` / `{MM}` / `{yyyy}` | `21` / `10` / `2026` |

Существующие цифры в тексте автоматически не переписываются. Дата берётся с ПК при открытии предпросмотра и фиксируется в этом задании. Пустой шаблон означает публикацию без комментария. Описания каналов пользователь настраивает сам в Studio; готовые комментарии передаёт своему агенту для внесения в шаблоны.

**Публикация.** Отметить аккаунты ✓ → верхняя кнопка «Опубликовать» (или контекстное меню конкретного аккаунта). В окне выбрать конкретные видео; справа/внизу виден точный текст комментария для выбранного ролика. Уже подтверждённые запланированные ролики отмечаются автоматически. Старые записи без статуса нужно выбрать вручную. Затем «Опубликовать выбранные».

Профили и ролики идут последовательно. Приложение открывает редактор по сохранённому ID, меняет доступ на Public и проверяет сохранение в отдельной вкладке. Если версия Studio требует сначала «Готово», а потом «Сохранить», обрабатываются оба шага. Затем открывается страница этого видео; комментарий разрешён только при наличии управления автора. Перед единственным нажатием отправки состояние сохраняется на диск и подтверждается приложением. Успех — видимый комментарий того же автора с точным текстом и ID. Лайки, просмотры по кругу, комментарии под чужими роликами и закрепление не выполняются.

## Ошибки и безопасное продолжение

- Нет сохранённого ID: сначала завершить/проверить загрузку в Studio. Не искать «похожий» ролик по названию и не передавать файл заново автоматически.
- Доступ не подтверждён: комментарий не отправляется. Открыть журнал и указанный ID; проверить, сохранилась ли смена доступа. Повтор публикации уже открытого видео не создаёт новый ролик.
- «Комментарий: проверить»: предыдущий запрос мог выполниться. Правой кнопкой по строке видео → «Открыть видео». Проверить комментарии именно этого ролика и аккаунта. Затем выбрать «Проверил: комментарий уже есть» либо «Проверил: комментария нет — разрешить повтор». Подтверждение вручную помечается отдельно от серверного подтверждения. Не редактировать XML вслепую, не обнулять защиту всей пачки.
- Комментарии отключены / нет управления автора / Google просит вход: остановиться и показать пользователю конкретную причину. Не переключать аккаунты, не пытаться обойти проверку.
- Кнопки RU/EN не распознаны: worker сохраняет диагностику и оставляет профиль для проверки. Передать JSON и журнал без токенов/сессий. Исправлять распознавание конкретного состояния; не добавлять бесконечные перезагрузки и клики по координатам.
- Остановка сохраняет уже подтверждённые публикации и неопределённые отправки. Продолжение учитывает сохранённое состояние после перезапуска программы.

## Проверки агента

1. Проверить Windows / Node / Dolphin, пути EXE и worker, новый маркер, сохранность аккаунтов и прокси.
2. Сначала один выбранный аккаунт и один согласованный ролик. Убедиться, что описание и теги Studio не изменились, заголовок переписан, превью есть, дата/время/пояс сохранены.
3. До финальной публикации показать пользователю выбранный ролик и текст в предпросмотре. Нажатие «Опубликовать выбранные» публикует сейчас, отменяя ожидание расписания для этих роликов.
4. После публикации сверить Public в Studio и комментарий на странице видео. Затем повторить на двух роликах: второй начинается после подтверждения первого; дублей комментария нет.
5. Проверить Stop / перезапуск: pending-комментарий требует ручной проверки; подтверждённый повторно не отправляется.

Автоматическая проверка ветки: все существующие Node-регрессии; Chromium-сценарии загрузки и нового публикационного потока на RU/EN; Windows-компиляция; тесты сериализации/даты/идемпотентности и снимки нативных окон. Фикстуры не подключаются к реальным аккаунтам. Это не заменяет проверку текущего интерфейса YouTube на ПК пользователя. Если реальный Studio отличается, не объявлять задачу успешной без сохранённого результата.
