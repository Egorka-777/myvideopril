## Установить целиком

1. Закрыть приложение. Сохранить резерв папки установки и `%LOCALAPPDATA%\VideoBatchDesktop`. Не очищать хранилище Telegram, аккаунты, шаблоны, историю, настройки Dolphin, Node/FFmpeg и модели Нарезчика.
2. Использовать отдельную рабочую папку, не затирая локальные правки:

```powershell
git clone --branch feat/telegram-connect-proxies-20261016 --single-branch https://github.com/Egorka-777/myvideopril.git myvideopril-telegram-connect
cd myvideopril-telegram-connect
dotnet build VideoBatch.csproj -c Release -p:ApplicationIcon=
```

3. Обновить установленный EXE/config **вместе с полной `tools/telegram` из этой ветки**. Сохранить существующие внешние компоненты. JS/package-файлы `tools/uploader` должны соответствовать ветке; при изменении lock выполнить `npm ci --prefix tools/uploader`. Не переносить чистые пользовательские папки поверх рабочих данных.
4. Python 3.11 x64 с Launcher. Выполнить подготовку из приложения или PowerShell:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\telegram\setup.ps1
```

Окружение Telegram отдельное от Нарезчика. Не удалять `python-socks`: без него Telethon может проигнорировать выбранный прокси. В журнале worker должна быть версия **`2026-10-16-telegram-connect-v2`**. Старый EXE с новым worker или обратная комбинация не считаются установкой обновления.

## Как теперь добавлять аккаунты

**Telegram → + Аккаунты → Выбрать папку / Выбрать файлы → выбрать прокси → Готово.** Можно перетащить источники.

Поддерживаются:

- `700001.json` рядом с `700001_tdata/tdata/key_datas` и внутренними файлами Telegram Desktop. Можно выбрать JSON, внешнюю папку `_tdata`, внутреннюю `tdata` или оба источника сразу: будет одна карточка.
- Папка с несколькими такими аккаунтами, ZIP, Telethon SQLite `.session` с одноимённым JSON.
- Без парного JSON TData читается сама; для .session без API-пары используется явно обозначенный профиль совместимости Telegram Desktop. Свой API остаётся опцией в **Настройки → Дополнительно**. Половина пары API в JSON считается ошибкой, а не смешивается с другой парой.

JSON ищется по точному имени папки/аккаунта. Посторонние JSON/README/изображения не превращаются в аккаунты. Если одновременно найдены два возможных источника для выбранного JSON, приложение сообщает неоднозначность. Если user_id в JSON и TData различаются — импорт отвергается. При сетевой проверке ожидаемый user_id также сравнивается с реальным аккаунтом.

Если у TData есть **локальный код-пароль**, он вводится в раскрываемом пункте «Дополнительно» мастера. Это не облачный пароль 2FA. Исходные файлы не изменяются. Импорт локальный; галочка «Проверить после добавления» запускает **отдельную** сетевую проверку после сохранения выбранного прокси. Для чистого офлайн-импорта снять галочку.

TData содержит ключ/DC/user_id, но не позволяет определить оригинальные API/модель устройства. При наличии совпадающего JSON берутся его данные; иначе используется профиль совместимости Desktop. «Без ручного API ID/Hash» не означает работу без протокола Telegram. Вставка обрезанного Auth Key со скриншота не является поддерживаемым источником: нужны полные файлы аккаунта. Не отправлять реальные ключи, JSON/TData или пароли в GitHub, чат или логи.

## Прокси

В Telegram есть отдельная вкладка **Прокси**:

- **+ Прокси** — вставить одну или несколько строк, по одной на строку: `socks5://user:password@host:port`, `socks4://...`, `http://...` или `host:port:user:password`. Значения разбираются автоматически; спецсимволы в URL-пароле должны быть URL-кодированы. Для IPv6 использовать URL с `[адрес]:порт`.
- **Из Dolphin** — читает полный адрес, порт, протокол, логин и пароль через сохранённый токен приложения. Получает сохранённые прокси и прокси тех профилей YouTube/TikTok, которые уже есть в приложении. Dolphin-браузер не запускается; сервер/прокси должен быть доступен с ПК самостоятельно. Обычный IP из ExpectedIp не подменяет настройки прокси. SSH-прокси пока не поддерживаются.
- При первом открытии Telegram с сохранённым токеном выполняется попытка получить прокси; ошибки/частичное получение видны во вкладке и журнале, не блокируют ручное добавление.
- Полные строки из общего раздела «Аккаунты» также добавляются в каталог. Старые назначения Telegram сохраняются.
- **По умолчанию** — заранее выбирает прокси в следующем импорте, не переключает существующие аккаунты. **Аккаунты → выбрать аккаунты → Назначить прокси** меняет именно выбранные карточки.
- Удаление прокси из каталога не переводит привязанные аккаунты напрямую: их сохранённый адрес остаётся. Для прямого подключения нужно явно выбрать «Без прокси». Неработающий назначенный прокси даёт ошибку, без скрытого обхода напрямую.

Адреса/логины/пароли хранятся в прежнем DPAPI-хранилище текущего пользователя Windows. В таблицах показываются имя и host:port; учётные данные не выводятся в журнал. У ранее импортированной карточки повторный импорт не сбрасывает имя, заметки или прокси. Это получение настроек Dolphin, а не постоянная фоновая синхронизация: после изменения настройки нажать «Из Dolphin» снова.

## Обязательная проверка на ПК

Сначала проверить **один** разрешённый владельцем аккаунт, без приглашений:

1. Открыть старое хранилище: все карточки и назначения на месте.
2. Получить прокси из Dolphin, сверить полный протокол/host/port/auth локально, не публикуя секреты. Проверить, что профили не запускались.
3. Выбрать реальный JSON рядом с `_tdata` из загрузки владельца, назначить конкретный прокси; импортировать с выключенной галочкой проверки. Должна появиться одна карточка, исходники неизменны.
4. Нажать «Проверить»: успешное имя/username/телефон должны принадлежать ожидаемому аккаунту. Повторный импорт, закрытие и открытие приложения не создают дубли и не теряют назначение.
5. Проверить ошибку недоступного прокси: подключение напрямую не допускается. Вернуть рабочий прокси.
6. Если реальный экспорт отличается от поддержанного формата — зафиксировать только безопасную структуру/имена полей, размер/тип файлов, код ошибки. Содержимое ключей/паролей в отчёт не включать. Не обещать успех до реального теста.

Автопроверки: синтетическая TData/SQLite/JSON, запрет сети во время импорта, точная вложенность экспорта, сохранность исходников и дедупликация, несовпадение user_id, прокси/авторизация/IPv6/HTTP:80, mock Dolphin (пагинация/частичная ошибка/без start/stop), DPAPI, реальный C#↔Python stdin UTF-8 протокол и локальный SOCKS5, существующие Telegram/Studio/JS регрессии. Реальная сессия владельца и реальный Dolphin-токен на стороне автора кода не использовались; окончательная проверка на этом ПК обязательна.
