## Как работает история

Общий журнал: `assembly-history/all-studios.xml` в каталоге данных Windows-пользователя. Старые файлы истории объединяются без удаления. Журнал атомарно сохраняется с backup; блокировка действует на один выбранный журнал.

В студии кнопка **«Журнал RU / EN / Общий»** выбирает, какой журнал расходуется. **RU** и **EN** хранятся отдельно (`assembly-history/markets/ru.xml`, `markets/en.xml`): одни и те же материалы можно собрать для русских каналов сегодня и для английских завтра без взаимного списания связок. Режим **Общий** — прежнее поведение (один журнал на все каналы). У каждого журнала свой файл блокировки; параллельная сборка RU и EN не мешает друг другу.

Комбинация определяется упорядоченными хэшами видеоматериалов, выбранных изображений по объектам и музыки современных студий. Новые имена файлов, заголовки, метки устройства, случайная точка начала и косметические настройки не открывают использованную связку. Перестановка материалов меняет комбинацию. Материалы могут повторяться в других сочетаниях; `Unique` отдельно запрещает повтор изображения, `Fixed` закрепляет CTA.

До публикации создаётся долговечный резерв. После перемещения готового MP4 он фиксируется. При аварии опубликованный результат фиксируется при следующей загрузке журнала; резерв с сохранившимся приватным файлом освобождается. Если оба файла исчезли и результат публикации неизвестен, резерв остаётся запрещённым: молча разрешать потенциальный повтор нельзя. Ошибка фиксации сохраняет результат и резерв, поэтому уже опубликованная связка не теряется.

Упорядоченные хэши сохраняются в журнале отдельно от результата. Для новых записей точный подсчёт не зависит от наличия MP4 или рецепта XML. Для сложных пересечений больших пулов и старых непрозрачных сигнатур без рецептов может остаться честная надпись `До …`. Запрет повторов работает и в этом случае. Утраченную до обновления историю нельзя достоверно восстановить без данных.

## Метаданные

Каталог: 15 брендов, 148 моделей из предоставленного пользователем списка. Это подписи по пользовательскому шаблону, которые не подтверждают фактическое устройство съёмки. Версии ОС не угадываются. Необязательный `Software` заполняется вручную; надпись Telegram не означает, что файл создан или отправлен Telegram.

В контейнер записываются `make/model`, `creation_time`, `creationdate`, `com.apple.quicktime.*` для Apple, `com.android.manufacturer/model` для остальных, необязательный `software`. После записи сборка читает файл и проверяет значения. MP4/MOV используют `use_metadata_tags`. Даты контейнера/дорожек — UTC, текстовая дата содержит смещение часового пояса компьютера.

Кодек, размер, FPS, длительность, битрейт и дорожки соответствуют реальному видео. Пример MOV с поворотом −90° не копируется как ложные параметры: в сборке вертикальность уже задана пикселями 9:16. GPS, дополнительная дорожка `apac` и BT.709 не приписываются отсутствующим данным. Формат сборки остаётся MP4.

Запись метаданных сборки — быстрое перепаковывание без повторного кодирования изображения/аудио. `.metadata.txt` теперь содержит отчёт, прочитанный из видео; `.assembly.xml` — рецепт, `.performance.xml` — замеры. Все они вынесены из основного списка роликов.

Также исправлена обработка аргументов FFmpeg: даты, stream selectors `0:0`, фильтры и URL в метках больше не считаются путями Windows из-за двоеточия.

Документация формата: https://ffmpeg.org/ffmpeg-formats.html и https://exiftool.org/TagNames/QuickTime.html. Сохранение и отображение тегов после обработки соцсетью не гарантируется.
