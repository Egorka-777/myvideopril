# Studio: часовой пояс и окончание планирования — v9

Ветка `fix/studio-timezone-finish-20261021` от актуального main `a4b013b13267b1c5ba15edf9dd5a156e79fbf087`. Включены текущие исправления Studio, прогревочные ролики и редактор субтитров. Обновление не требует сбрасывать аккаунты/прокси, переимпортировать Telegram или перезапускать профили Dolphin.

## Причина и границы подтверждения

На предоставленном скриншоте время **14:45** уже введено, кнопка «Запланировать публикацию» активна, список поясов открыт. На втором скриншоте ошибка: **«Studio не показал пояс ПК UTC+7 · страница не отвечает»**.

Код main/v8 считывал каждый пункт меню отдельными CDP-вызовами (`isVisible`, `innerText`, `evaluate`) внутри одного прохода с бюджетом 5 секунд. Большой список/задержка CDP могли исчерпать бюджет и дать ложное сообщение о зависшей странице. Обычный `select/option` вовсе не поддерживался. В тесте выполняется старый код из main `a4b013b`: отдельно воспроизводятся отсутствие поддержки select и ложное зависание на длинном меню с задержкой CDP. Тип DOM-контрола именно в живом профиле подтверждается диагностикой, одного изображения для этого недостаточно.

Также исправлены асинхронный сброс времени после смены пояса и проверка сохранённого расписания: при повторном открытии Studio может отображать тот же момент в поясе браузера. Сравнивается UTC-момент, а не только текст одинаковых часов.

1. Остановить задания и закрыть VideoBatch. Сохранить резервную копию EXE/DLL/runtimes, `tools/uploader` и пользовательских настроек. Незавершённый мастер Studio не перезагружать и автоматически повторно не отправлять файл.
2. Скачать **VideoBatch-Studio-Timezone-Update** из успешного Actions **YouTube Studio RU EN upload** именно этой ветки. Проверить `SOURCE_COMMIT.txt` по коммиту запуска.
3. В текущей установке заменить EXE, DLL/runtimes и **все** `tools/uploader/*.js`, `package.json`, `package-lock.json` из архива. **Обязателен новый `studio-timezone-controls.js`**, а также действующий `studio-schedule-controls.js`. Обновить только worker.js недостаточно. Установленный node.exe сохранить; зависимости — `npm ci --prefix tools/uploader --ignore-scripts`.
4. Остальные tools и пользовательские данные оставить. Не откатывать генератор прогревочных роликов или редактор субтитров к предыдущим сборкам. Из исходников: `git fetch origin`, `git switch fix/studio-timezone-finish-20261021`, `git pull --ff-only`, `dotnet build VideoBatch.csproj -c Release -p:ApplicationIcon=`. Местные правки предварительно сохранить и объединить, без reset/clean.
5. В журнале нового задания должен появиться **`2026-10-21-studio-timezone-v9`**. Если виден v7/v8 — проверить фактический EXE, путь worker и соседний uploader, а не создавать новые аккаунты.

## Что делает v9

- Определяет нативный `select` с `option` и меню Studio. Читает весь список одним браузерным снимком, а не сотнями CDP-вызовов.
- Для select использует Playwright `selectOption`, не пытаясь кликнуть невидимый HTML-option. Поддерживает IANA-значения и числовые значения option с явной меткой GMT. Формат `((GMT+0300)) Местное время`, UTC/GMT, получасовые/четвертьчасовые смещения распознаются.
- Выбирает IANA-пояс ПК, когда он есть; иначе пояс с тем же смещением **на дату публикации**. Не меняет настройки антидетект-профиля/часовой пояс всего браузера.
- Устанавливает дату и время, выбирает пояс, затем восстанавливает сброшенные поля. Проверяет стабильность даты/времени/пояса/UTC-момента перед кнопкой. Восстановление ограничено тремя проходами; нет бесконечной перезагрузки и повторной загрузки файла.
- Не ищет «Далее» на последнем экране. Дожидается доступной «Запланировать» и нажимает один раз. Ошибку «в прошлом» проверяет и во время ожидания кнопки, а не только в начале.
- После сохранения открывает отдельную проверочную вкладку, читает статус, дату, время и пояс и проверяет тот же UTC-момент. Проверочную вкладку закрывает. Другой показанный пояс с корректно пересчитанными часами сам по себе не считается ошибкой; другой момент времени блокирует продолжение очереди.
- Названия, описания, превью и прежняя последовательная очередь сохранены. После ошибки и Stop незавершённый мастер остаётся открытым, профиль автоматически не перезапускается.

## Проверка на ПК

Сначала проверить уже созданный черновик/расписание в Studio, чтобы не сделать дубль. Эта правка **не добавляет автоматическое возобновление старого незавершённого мастера**. Для нового контрольного прогона взять один файл и будущий слот с запасом на загрузку; затем — два файла для проверки очереди.

Ожидаемые этапы:

1. «Список поясов: стандартный select» либо «меню Studio» с фактически выбранной меткой.
2. «Подтверждён пояс … (UTC+7)» либо «Часовой пояс уже верный …».
3. Если Studio сбросил время: «восстанавливаю расписание (1/3)», затем правильные дата/время.
4. «Проверено перед нажатием: … UTC7. Кнопка … доступна».
5. «Нажимаю … один раз» → проверка сохранённых метаданных и расписания → «Studio подтвердил расписание …».

В приложении больше не нужно вручную менять порядок даты/времени/пояса ради обхода ошибки. При повторном открытии страницы проверить также, что дата/время относятся к выбранному на экране поясу, а не к часовому поясу на странице просмотра YouTube.

## Если снова ошибка

Не советовать бесконечно «перезапустить». Сохранить полный текст этапа и `diagnostics/youtube-studio-*.json` из папки данных приложения, а также SOURCE_COMMIT. В JSON теперь есть `timezones.controls`: tag/id, выбранные value/label, тип select/меню, список часовых поясов и выбранные пункты. Это данные интерфейса; cookies, токены и пароли специально не собираются. В случае отсутствия точного пояса или неоднозначного контрола процесс останавливается до подтверждения, чтобы не назначить другой момент публикации.

При «время уже прошло» нужен новый будущий слот. При правильном времени и недоступной кнопке проверить сообщение самого Studio. Не добавлять обход блокировок YouTube, не делать случайные клики, прямые запросы публикации, смену прокси и повторную отправку файла.

Официальные ссылки: [Playwright: selectOption](https://playwright.dev/docs/input#select-options), [YouTube: отложенная публикация](https://support.google.com/youtube/answer/1270709?hl=ru).
