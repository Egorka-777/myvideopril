# Инструкция агенту на ПК: стабильность профилей и удаление аккаунтов

## 1. Что делать

Репозиторий: https://github.com/Egorka-777/myvideopril

**Ветка с готовыми изменениями: `fix/profile-stability-account-delete-20261005`.**
Основа: `fix/youtube-mesh-crosswatch-20261001`, исходный коммит `7a52ce6`.
Не бери `main`: в нём другой сценарий просмотра. Не переноси исправления по памяти из других веток.

Твоя задача — собрать эту ветку отдельно, установить полный комплект в новую папку и проверить его на Windows с Dolphin пользователя. Изменения уже написаны. Не переписывай их заново. Если проверка выявит дефект, исправляй только в этой ветке и повторяй соответствующий тест.

Данный документ задаёт порядок проверки этой версии. Старые документы про обязательное закрытие пачки или постановку видео на паузу описывают прошлые версии и здесь не применяются.

## 2. Требования к результату

1. После просмотра, частичной ошибки и нажатия «Стоп» профили Dolphin остаются открытыми.
2. Повторный запуск подключается к тому же браузеру, когда доступен подтверждённый CDP. Существующие вкладки пользователя не используются для навигации задания.
3. Нельзя закрывать/перезапускать уже открытый профиль ради восстановления подключения.
4. «Стоп» прекращает задание, а не закрывает профиль. В YouTube worker закрывает только свою вкладку; если она последняя, сначала создаёт пустую вкладку. Если worker не завершился за 3 секунды, C# завершает его процесс, но не вызывает Dolphin `/stop`.
5. Ошибка остаётся ошибкой. Частичный результат не превращается в полный успех. Остальные каналы обрабатываются в существующем порядке.
6. Удаление доступно правой кнопкой в YouTube и TikTok. В разделе «Профили» доступно через правую кнопку и `⋯`.
7. В YouTube удаляется выбранная строка, а не все строки с тем же Profile ID. В TikTok — выбранная строка TikTok. В «Профили» — связанные строки обеих платформ, перечисленные в подтверждении.
8. Удаление касается только списков приложения. Профиль Dolphin, аккаунты на платформах, публикации, исходные файлы и история задач не удаляются.
9. Удалённый TikTok не появляется заново после автоматического импорта из YouTube или перезапуска. Добавить его вручную разрешено.
10. Во время активной операции удаление блокируется. После «Стоп» нужно дождаться фактического завершения операции.

Просмотр запускается пачками по 5, но завершённые профили остаются открытыми. Это не ограничение общего числа открытых окон пятью. Не возвращай закрытие окон для соблюдения старого ограничения.

В обычных загрузках используется существующая настройка `KeepDolphinProfileOpenAfterUpload`: значение `true` сохраняет профиль. Установи её через настройки приложения, если пользователь хочет сохранять новые профили после загрузки. Профиль, к которому подключились повторно по сохранённому CDP, сохраняется независимо от этой настройки. После ошибки профиль не закрывается. Повтор публикации автоматически не выполняется.

## 3. Что установлено по логам и коду

В переданных логах есть `page.evaluate: TypeError: Failed to fetch` при чтении метаданных YouTube и отказ подключиться к открытому профилю. Есть строка «Dolphin подтвердил закрытие профилей»: это было обязательное закрытие в C# после каждой пачки, включая ошибку.

Сетевой сбой подтверждён. Конкретная причина сети или прокси не установлена: одного `Failed to fetch` для этого недостаточно. Не заявляй, что прокси неисправен, без отдельной проверки.

В исходном коде YouTube HTTP worker сообщал, что профиль сохраняется, но C# после успешной загрузки всё равно вызывал `/stop`. Это исправлено. Слепой перезапуск с повтором Studio-публикации также убран: потерянный ответ может скрывать уже созданное видео.

## 4. Ограничение Dolphin — не выдумывать поддержку

Официальная документация требует `automation=1` для запуска управляемого профиля и возвращает `automation.port` и `automation.wsEndpoint`:

https://docs.dolphin-anty.com/en/api/basic-automation-dolphin-anty

Спецификация: https://docs.dolphin-anty-cdn.com/openapi.yaml

Обычное окно, запущенное вручную без автоматизации, может не иметь CDP. Документация не подтверждает возможность включить CDP в уже работающем обычном окне. Нельзя обещать такое подключение и нельзя изобретать API endpoints.

Эта версия сохраняет CDP, полученный при запуске через приложение, отдельно для Profile ID и локального порта Dolphin. Перед повторным использованием проверяет `/json/version` и UUID браузера: совпадение только номера порта недостаточно. Кэш находится в `%LOCALAPPDATA%\VideoBatchDesktop\dolphin-sessions`. Он не содержит токен, cookies или пароль.

Если профиль уже открыт, но CDP неизвестен, приложение сохраняет окно и честно сообщает ограничение. Не закрывай окно автоматически. Для проверки сценария открытого профиля сначала запусти его через новую версию приложения, затем повтори операцию с тем же открытым профилем. Отдельно проверь вручную открытый профиль: если CDP не предоставлен, зафиксируй этот случай как ограничение интеграции, а не как успех.

Не сканируй произвольные порты. Не подключайся к браузеру другого аккаунта. Не удаляй кэш вручную «для лечения», пока не сохранил диагностику; устаревшая запись и так проверяется и не используется.

## 6. Подготовить установку

1. Найди действующую папку установки. Если EXE запущен: `Get-Process VideoBatch -ErrorAction SilentlyContinue | Select-Object Id,Path`. Используй реальный путь. Не угадывай расположение.
2. Убедись, что в старом комплекте есть `tools\uploader\node.exe`, `tools\uploader\node_modules\playwright-core`, `tools\ffmpeg.exe`, `tools\ffprobe.exe`. Это аргумент `RuntimeDirectory` для сборки.
3. Сначала останови активные задания через интерфейс и дождись их завершения. Закрой только старое приложение VideoBatch. Не закрывай открытые окна Dolphin для этой установки.
4. Сделай резервную копию всей папки `%LOCALAPPDATA%\VideoBatchDesktop` в отдельную папку с датой. Проверь, что копия содержит `settings.xml`, если он существовал. Сохрани локальные очереди и каталоги вместе с настройками. Не добавляй эту копию в git и не публикуй её.
5. Старый комплект не перезаписывай. Новая папка должна быть отдельной. Обе версии используют общие локальные настройки: не запускай их одновременно.

## 7. Проверки и сборка

Нужны Windows 10/11, .NET Framework 4.8, .NET SDK и Node из рабочего комплекта. Скрипт запускай через **Windows PowerShell `powershell.exe`**, не через `pwsh`: встроенные C# self-tests используют .NET Framework.

Подставь реальные пути вместо `<...>`; эти строки не являются готовыми значениями:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\Build-ProfileStability-20261005.ps1 -RuntimeDirectory "<папка старого комплекта>" -OutputDirectory "<новая папка комплекта>"
```

Скрипт запускает все `tests\*.js`, собирает EXE, выполняет `HttpRegressionSelfTests.RunAll`, копирует runtime из старой установки и **все JS из текущей ветки**. Сверяет хэши всех JS и создаёт `SOURCE_COMMIT.txt`, `START_HERE.txt`, `SHA256_MANIFEST.txt`.

Обязательно должны попасть новые `dolphin-session.js`, обновлённые `worker.js`, `worker-http.js`, `worker-tiktok.js`, `worker-tiktok-http.js`, `youtube-open-today.js` и существующий `youtube-playback.js`. Копировать один EXE или один worker недостаточно. Скрипты из старой установки использовать нельзя.

Дополнительно выполнить browser tests на исходном клоне:

```powershell
npm ci --prefix tools/uploader --ignore-scripts
npx --prefix tools/uploader playwright-core install chromium
node tests/browser/youtube_navigation.js
node tests/browser/youtube_watch_grid.js
node tests/browser/native_calendar.js
node tests/browser/dolphin_lifecycle.js
```

После **каждой** команды проверь `$LASTEXITCODE`. Ненулевой код — остановить дальнейшую установку и разбирать ошибку. Отсутствие строки `OK` или явного подтверждения проверки нельзя считать прохождением теста.

## 8. Живая проверка на ПК — обязательный список

Запусти EXE из нового комплекта. Проверь журнал: `Worker 2026-10-05-profile-stability-v1`. Если показывается старая версия, проверь путь EXE и папку `tools\uploader`; не начинай проверку старого worker.

1. **Закрытый профиль:** выбери один тестовый аккаунт, запусти требуемую операцию. По её окончании окно Dolphin остаётся открытым. Результат операции подтверждён, не только отправлен запрос.
2. **Повтор:** не закрывая это окно, запусти операцию ещё раз. В журнале есть подключение к существующему браузеру; окно и пользовательские вкладки сохранились. Повторный запуск нового браузера не нужен.
3. **Перезапуск приложения:** заверши задания, закрой VideoBatch, оставь Dolphin открытым. Снова запусти новый EXE и повтори операцию на этом профиле. Подключение восстанавливается через сохранённый проверенный CDP.
4. **Профиль без CDP:** проверь вручную открытое окно, которое новая версия ещё не запускала. Если Dolphin не даёт адрес — фиксируй понятное сообщение ограничения. Окно не закрывается и не перезапускается. Не выдавай это за прошедшее подключение.
5. **Сбой сети:** на отдельном тестовом профиле воспроизведи краткий сетевой сбой без изменения остальных профилей. Для метаданных видно не более трёх попыток чтения; затем проверка отдельной вкладкой того же профиля. После исчерпания попыток остаётся ошибка и диагностика, а не фиктивный успех. Окно остаётся открытым.
6. **Частичный результат:** один недоступный канал/ролик среди доступных. Оставшиеся обрабатываются. Итог содержит фактическое количество успехов и ошибок. Не исправляй тест удалением ошибки из отчёта.
7. **Стоп:** нажми «Стоп» в середине операции. Дождись завершения worker. YouTube прекращает задание и закрывает свою вкладку; пользовательские вкладки и профиль остаются. Если вкладка была последней, остаётся пустая вкладка.
8. **Пачки:** больше пяти выбранных профилей — следующая пачка запускается после завершения заданий текущей. Завершённые окна остаются открытыми. RU/EN и кросс-просмотр сохраняют имеющуюся логику выбора каналов.
9. **Удаление YouTube:** ПКМ по строке → «Удалить аккаунт из приложения» → сначала «Нет» (строка сохраняется), затем «Да» (строка исчезает). Другие строки с тем же Profile ID сохраняются. Файлы и профиль Dolphin остаются.
10. **Удаление TikTok:** удалить строку, открыть другой раздел, вернуться, обновить, перезапустить EXE. Строка не возвращается из YouTube. Затем вручную добавить аккаунт с тем же ID — добавление разрешено.
11. **Удаление «Профили»:** удалить тестовый объединённый профиль. Связанные строки исчезают из обоих разделов; остальные профили сохранены. Проверь также ПКМ и меню `⋯`.
12. **Удаление во время задания:** команда блокируется без изменения списков. После фактического завершения операции удаление доступно.
13. **Сбой сохранения:** это покрывает `RunAccountRemovalSelfTest`: при исключении записи восстанавливаются исходные объекты и списки, удаление не отображается как успешное. Не порти настоящие настройки ради этого теста.
14. **Загрузка:** действующую настройку сохранения профиля проверять на явном тестовом задании. Не перезапускай автоматически публикацию после потерянного ответа; сначала сверяй реальное наличие созданного ролика. Не публикуй дополнительные ролики лишь ради проверки интерфейса удаления.

## 9. Где смотреть причины

Общий журнал приложения показывает аккаунт, этап, попытку, HTTP-статус, длительность подключения и итог. YouTube metadata retry показывает video ID и номер попытки. Диагностика навигации сохраняется в `%LOCALAPPDATA%\VideoBatchDesktop\diagnostics\youtube-navigation-*.json` и `.png`. HTTP worker продолжает писать существующие `http-*.jsonl`.

Не записывай и не отправляй токен, cookies, Authorization или полный ответ API с приватными данными. Не публикуй пользовательские логи и настройки в публичном репозитории. Если нужен отчёт — сохраняй только обезличенные результаты и причины.
