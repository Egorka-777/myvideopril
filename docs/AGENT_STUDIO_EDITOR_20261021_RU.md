# Studio: старт, фокус и ввод метаданных — v11

Ветка `fix/studio-editor-focus-20261021` от main `cae5217ddec22d305543ab9bef30493e57defe32`. Включает текущий v9 с часовыми поясами, актуальные банки описаний RU/EN (`c8349e2`), прогревочные ролики и редактор субтитров. Сброс аккаунтов, прокси, профилей, Telegram и шаблонов не нужен.

## Причина

Присланная ошибка: «Studio не активировало поле ввода — возможно, его перекрывает подсказка или затемнение». Проверка v10 сравнивала редактируемый элемент с `document.activeElement`. В открытом Shadow DOM на уровне документа активным считается внешний компонент, а настоящий редактор находится в `shadowRoot.activeElement`. Поэтому старый код мог остановиться даже при фактически полученном фокусе. В тесте запускается старый код из main `cae5217`: он выдаёт эту ошибку, а независимая проверка внутри shadowRoot подтверждает, что поле уже сфокусировано. По одному скриншоту нельзя подтвердить полный DOM живой страницы, поэтому новая диагностика сохраняет фактическую структуру фокуса.

Дополнительно убраны три Escape подряд, синтетический `el.click()` и принудительный клик сквозь перекрытие. Видимый `.dialog-scrim` за окном сам по себе не означает, что поле перекрыто. Это обычный фон модального окна. Прежние Escape могли закрыть незавершённый мастер вместо подсказки.

## Установка

1. Остановить задачи, закрыть VideoBatch. Сохранить резервную копию EXE/DLL/runtimes, `tools/uploader` и пользовательских данных. Открытый незавершённый мастер не перезагружать, видео автоматически повторно не отправлять.
2. Скачать **VideoBatch-Studio-Editor-Update** из успешного Actions **YouTube Studio RU EN upload** ветки `fix/studio-editor-focus-20261021`. Сверить `SOURCE_COMMIT.txt`.
3. Заменить EXE, приложенные DLL/runtimes, **все JS** из `tools/uploader` и package-файлы. Новые/обязательные модули: `studio-editor-controls.js`, `studio-timezone-controls.js`, `studio-schedule-controls.js`. Не копировать один worker.js. Сохранить установленный node.exe и остальные инструменты; `npm ci --prefix tools/uploader --ignore-scripts`.
4. Из исходников: сохранить местные изменения, `git fetch origin`, `git switch fix/studio-editor-focus-20261021`, `git pull --ff-only`, `dotnet build VideoBatch.csproj -c Release -p:ApplicationIcon=`. Без reset/clean и отката банков описаний из main.
5. В журнале нового запуска должен быть **`2026-10-21-studio-editor-v11`**. При v10 или более старом маркере проверять фактический путь EXE и uploader. Аккаунты переимпортировать не нужно.

## Что изменилось

- Фокус проверяется по всей цепочке открытых Shadow DOM, включая вложенные компоненты. Не требуется активность всего окна Windows: другие профили могут быть открыты одновременно.
- Проверяется доступность самого поля, его `readonly`/`inert` и реальное перекрытие в точке ввода. Обычный фон модального окна не блокирует ввод.
- Только подтверждённую подсказку поверх поля можно закрыть Escape (один раз за попытку активации). Постороннее модальное окно не обходится принудительными кликами. Мастер не закрывается серией Escape.
- Текст очищается клавишами и печатается. Проверяются введённые части и итог после Tab, включая длинные описания. Веб-странице не присваиваются innerText/textContent и не используется вставка из буфера.
- При замене поля во время загрузки компонентов повторяется **только ввод этого поля** с очисткой и полной проверкой, максимум две попытки. Файл, «Запланировать» и «Опубликовать» этот механизм повторно не отправляет.
- Блоки рекламы и ИИ распознаются и внутри Shadow DOM, сохраняется раздельный ответ «Нет» по настройкам приложения. Переходы, превью, описание, очередь и проверка сохранённого расписания остаются в общей цепочке.
- В диагностике поля есть `focused`, `shadowDepth`, фактический активный tag/id/role и перекрывающий элемент, без текста описания, ключей и cookies.

## Автопроверка агента

Из **корня репозитория**, не из папки установленного EXE:

```powershell
npm ci --prefix tools/uploader --ignore-scripts
npx --prefix tools/uploader playwright-core install chromium
git fetch --no-tags origin cae5217ddec22d305543ab9bef30493e57defe32 --depth=1
node tests/browser/studio-editor-focus.js
node tests/browser/studio-details-chain.js
node tests/browser/studio-timezone-finish.js
```

Новый тест проверяет ложную ошибку v10 на настоящих вложенных Shadow DOM, фоновое затемнение, одну перекрывающую подсказку, отказ при постороннем модальном окне, замену поля во время печати, безопасную диагностику и RU/EN-цепочку двух роликов: файл → название/описание → теги → реклама/ИИ → пояс → одно планирование → проверка сохранения. Дополнительно проверяются отдельные shadow-компоненты рекламы/ИИ без стабильных id. Старые тесты включают запуск Dolphin/CDP, выбор файла, превью, календарь, последовательную очередь и сохранённые данные. Это изолированные браузерные страницы без реальной публикации.

## Проверка на ПК

Сначала проверить созданные черновики в Studio, чтобы не сделать дубль. Автоматического возобновления старого незавершённого мастера нет. Для нового прогона — один файл, затем два подряд. Для длинных видео использовать будущие слоты с запасом на загрузку.

Ожидается: файл передан → поле названия готово → название введено → поле описания готово и счётчик введённых символов → настройки рекламы/ИИ → переходы → проверенное расписание → одно нажатие → подтверждение сохранения. Маркер v11 обязателен. Если поле заменилось, допустима одна строка о повторном вводе поля, затем должна пройти проверка точного текста.

При новой ошибке не заставлять пользователя повторно запускать всё вслепую. Сохранить текст этапа, SOURCE_COMMIT и `diagnostics/youtube-studio-*.json` из папки данных приложения. Если обнаружено отдельное окно поверх редактора — смотреть его назначение; не удалять DOM-элементы, не добавлять force-клики и не отключать проверки. Ошибка доступности поля не означает неисправный аккаунт или прокси.

На реальных аккаунтах в среде разработки публикация не выполняется. Контрольный прогон на ПК остаётся необходимым, поскольку тестовые страницы не доказывают совпадение всех вариантов текущего интерфейса YouTube.

Документация: [Shadow DOM и локаторы Playwright](https://playwright.dev/docs/locators#locate-in-shadow-dom), [activeElement](https://developer.mozilla.org/en-US/docs/Web/API/Document/activeElement).
