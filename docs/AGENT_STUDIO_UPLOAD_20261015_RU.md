# Агенту на ПК: обновить загрузку через YouTube Studio

Репозиторий: `Egorka-777/myvideopril`. Ветка: `feat/studio-upload-ru-en-20261015`.
Основа — актуальная main `e0390f0`, включая четыре профиля сборки и исправления Нарезчика. Новая кнопка по умолчанию — **Через Studio**, быстрая загрузка остаётся отдельной второстепенной кнопкой.

## Установка

1. Закрыть VideoBatch. Скопировать в резерв папку установки и `%LOCALAPPDATA%\VideoBatchDesktop` (settings.xml, аккаунты, секреты, шаблоны, история и материалы).
2. В отдельной рабочей папке:

```powershell
git clone --branch feat/studio-upload-ru-en-20261015 --single-branch https://github.com/Egorka-777/myvideopril.git myvideopril-studio
cd myvideopril-studio
npm ci --prefix tools/uploader --ignore-scripts
dotnet build VideoBatch.csproj -c Release -p:ApplicationIcon=
```

3. В действующую установку перенести новый `VideoBatch.exe`, config и **все JS** из `tools/uploader`, включая новый **youtube-studio-upload.js**, worker.js, youtube-thumbnail.js и библиотеки Dolphin. Перенести package.json/package-lock.json, выполнить `npm ci --prefix tools/uploader --ignore-scripts` в установке, если зависимости не подготовлены. Сохранить node.exe, FFmpeg, данные Нарезчика и пользовательские файлы. Обновлять EXE и worker вместе: между ними новый протокол сохранения состояния. После обновления лог должен показывать `2026-10-15-studio-sequential-ru-en-v1`.
4. Открыть YouTube, выбрать нужный RU/EN и канал. В **Ещё → Настройки Studio** видны два переключателя: прямая реклама и использование ИИ. По заданным пользователем настройкам по умолчанию оба **Нет**; если конкретный материал требует раскрытия, выбрать **Да** до старта очереди. Значение проверяется в отдельном блоке Studio, а не через первую попавшуюся кнопку «Нет».
5. Добавить пять видео и проверить назначенные заголовки в приложении. Нажать **Через Studio**, проверить предпросмотр расписания по времени компьютера. Публикация идёт последовательно в одном профиле: один файл → его данные → подтверждение расписания → следующий файл.

## Исправления

- Прежний Studio-путь не передавал описания и теги. Теперь они попадают в каждый элемент задания. RU берёт доступный банк описаний и существующий футер тегов; EN — `YouTubeDescriptionBankEn`, с резервом из `TikTokDescriptionBankEn`. Если для EN банка нет, сохраняется собственное описание из настроек канала Studio. Для разных профилей используется стабильный сдвиг по банку: это варианты из существующих текстов, а не создание новых. Уникальность для всех аккаунтов не гарантируется, особенно если вариантов меньше аккаунтов. Если нужны строго разные тексты каждому каналу, отдельно подготовить достаточный банк и проверить распределение.
- Служебные индексы вроде `001.`, `[01]`, суффикс копии `(2)` и расширение файла очищаются. Числа внутри смысла (`3 правила`, `2026`, `12.34`) сохраняются. Studio не дописывает индексы ради уникальности заголовка и не обрезает его молча до 100 символов.
- Заголовок очищается через Ctrl+A/Delete, затем вводится последовательно с небольшой задержкой; описание и теги вводятся клавиатурой. После ввода читается фактическое значение. Это UI-автоматизация; способ ввода не доказывает, что платформа воспримет загрузку как ручную.
- Аудитория, прямая реклама, использование ИИ — разные области. Поддержаны RU/EN и старый флажок рекламы. Отсутствие однозначного обязательного элемента — ошибка с диагностикой, без кликов по похожим элементам страницы.
- Время берётся из Windows: для каждого ролика передаются дата/время, Unix-момент и смещение именно на дату публикации. Node проверяет их согласованность. В рабочей вкладке применяется пояс ПК, если Dolphin разрешает это; при закреплённом поясе браузера в Studio явно выбирается пояс ПК. Перед сохранением и после перезагрузки проверяются дата, время и выбранный пояс Studio. Просроченный слот останавливает загрузку вместо немедленной публикации.
- Планирование работает через календарь/контролы Studio. Нет подмены ошибочного расписания сохранением черновика. Старые вспомогательные функции остаются для совместимости тестов/старых команд, но новая запланированная Studio-очередь использует отдельный последовательный модуль.
- Перед передачей файла приложение сохраняет `StudioPending` и постоянный ID в settings.xml, затем подтверждает worker. Если сохранение не удалось, файл не отправляется. После создания запоминается ID YouTube. Успех фиксируется после открытия редактора по **конкретному ID**, проверки заголовка/описания/тегов/раскрытий и расписания. Превью, если назначено, также проверяется сохранённым изображением.
- У подтверждённого ролика сразу сохраняется PublishedUrl/Id. После ошибки/закрытия программы неопределённая попытка остаётся заблокированной, чтобы не отправить тот же ролик автоматически ещё раз. Остальные подтверждённые результаты сохраняются.
- Для разблокировки после **ручной проверки Studio**: выбрать канал → **Ещё → Studio: сбросить защиту после ручной проверки**. Если видео уже запланировано, не сбрасывать для повторной загрузки: сначала внести его подтверждённую ссылку в приложение/обработать существующий ролик. Сброс нужен для попытки, которую человек проверил и решил начать заново.
- Оригиналы читаются по исходным путям. Загрузчик не делает новые копии видео и не переименовывает исходники. Для неоднозначной передачи файла нет автоматической повторной отправки.
- Если сохранён явный `.../channel/UC…`, перед стартом сверяется открытый канал. При URL только с @handle учётная запись определяется выбранным Dolphin-профилем; перед тестом проверить, какой канал открыт в нём.

## Проверка на настоящем профиле

Браузерные тесты используют локальные модели экранов RU/EN, а не настоящий авторизованный YouTube. Документация подтверждает основные шаги, но не каждый вариант DOM/эксперимента Studio. Поэтому нельзя объявлять поддержку всех вариантов интерфейса на 100% без прогона на ПК пользователя.

1. Начать с **одного** ролика с публикацией достаточно далеко в будущем. Проверить правильный выбранный канал Dolphin.
2. Убедиться, что прежнее файловое имя действительно стирается, вводится заголовок из приложения; описание и теги соответствуют выбранному языку/банку.
3. Проверить два ответа «Нет» в отдельных областях (либо выбранные пользователем «Да»), а также «не для детей» для соответствующего контента.
4. Сравнить время Windows, предпросмотр приложения и **выбранный пояс внутри Studio**. Проверить сохранённое расписание после закрытия и повторного открытия редактора.
5. Затем пять видео: отдельные ID, разные назначенные заголовки/свои данные, последовательная обработка, сохранение ссылки после каждого результата.
6. Остановить попытку до подтверждения и перезапустить приложение: неопределённый ролик не должен загружаться повторно сам. Проверить его вручную в Studio перед сбросом защиты.
7. Если интерфейс отличается, взять общие логи `diagnostics\app-*.jsonl` и `diagnostics\youtube-studio-*.json`. В JSON пишутся видимые названия/ID контролов и этап ошибки; куки/токены и полный текст описания туда не записываются. Не заменять проверку расписания обходным кликом Publish/Save.
