# Исправление входа Telegram после проверки на ПК

Ветка разработки: `fix/telegram-login-diagnostics-20261017` (слита в **`main`**).
Worker / runtime: **`2026-10-17-telegram-login-v3`**. Базовый сценарий импорта — **`docs/AGENT_TELEGRAM_CONNECT_20261017_RU.md`**. YouTube автопрогрев на `main` — коммит `0973704`.

## Что показал скриншот и что исправлено

На скриншоте `041917` TData уже импортирована, но состояние «Только Web» остановило открытие аккаунта до действительного подключения сессии.
Это сообщение было результатом предварительного TCP-пробника. Оно не доказывало ни блокировку аккаунта, ни принципиальную непригодность прокси.

1. Пробник больше не запрещает реальную попытку входа. Проверка аккаунта выполняет подключение и `get_me` через назначенный прокси.
2. При импорте TData теперь читается сохранённая сетевая конфигурация, а не единственный жёстко заданный IP.
   В opentele 1.15.1 обнаружена воспроизводимая ошибка: `MTP.Config.FromSerialized` читает `dcOptionsSerialized`, но не применяет его через `constructFromSerialized`.
   Приложение явно читает этот блок по структуре официального Telegram Desktop. Криптография/ключи читаются существующим opentele; исходники не изменяются.
   В тестовой записи сетевой конфигурации учтён ещё один дефект WRITER библиотеки: `DcOptions.Serialize` пропускает port. Поэтому регрессионная фикстура использует официальный бинарный формат с port. Приложение саму TData не записывает.
3. До трёх адресов ТОГО ЖЕ DC проверяются последовательно при сетевой ошибке. Используются тот же ключ и тот же прокси, без прямого выхода и смены аккаунта. Ошибка отзыва сессии, неправильная идентичность, ограничения Telegram не обходятся повтором на другом адресе.
   Общий бюджет попыток — 22 секунды плюс ограниченное закрытие соединений и до 7 секунд диагностики Web после неудачи.
4. Разрешены адреса из опубликованных сетей Telegram и явный дополнительный адрес из встроенного списка официального Desktop. Произвольные IP/локальные адреса из загруженных файлов не используются.
5. Рабочий адрес сохраняется в зашифрованном vault. Событие с сессией не выводится в журнал.
6. «Открыть Telegram» сразу открывает официальный Web A; импортированная сессия подключается один раз для подтверждения свежего QR. Дублирующей предварительной проверки нет. При неудаче видна причина; страница остаётся доступна для обычного входа владельца. Запрос 2FA выполняется на официальной странице.
7. Проверка прокси отдельно показывает Web и DC назначенных аккаунтов (либо тестовый DC2, если назначений нет). Проверки туннелей идут параллельно с общим пределом одной попытки 7 секунд; это не подтверждение авторизации аккаунта.

**Не установлено:** точная внешняя причина отказа конкретного прокси пользователя. Его TData и сессия здесь не предоставлялись. Исправленные дефекты не означают, что действительность аккаунта/пароля или доступ провайдера уже проверены.

## Установка агентом

1. Закрыть приложение. Сохранить установленную папку и данные Telegram (`telegram.vault`, `web`, настройки). Не удалять файлы и не сбрасывать сессии.
2. ```powershell
   git fetch origin
   git switch main
   git pull --ff-only
   ```
   Локальные изменения сохранить отдельно; не использовать `reset --hard` / `clean` на данных Telegram.
3. Скачать **Telegram-Login-Update** (или **Telegram-Connect-Update**) из успешного **Telegram workspace** на SHA **`main`** / `SOURCE_COMMIT.txt`. Установить EXE, DLL, оба каталога `runtimes`, `tools/telegram`, `tools/uploader`.
   Существующие Node/node_modules, FFmpeg и материалы пользователя оставить. Альтернатива: `dotnet build VideoBatch.csproj -c Release -p:ApplicationIcon=` и установка полного выхода.
4. Telegram → Настройки → **Подготовить Telegram**. Версия среды — `2026-10-17-telegram-login-v3`; нужна работающая среда Python 3.11 x64 и WebView2 Runtime. Старый `runtime.ready` сам по себе больше не принимается.
5. **Повторно импортировать исходную папку TData пользователя через «Добавить аккаунт → Открыть… → Папка TData».** Старый импорт не сохранил сетевую конфигурацию, восстановить её из одной старой записи vault нельзя. Тот же ключ обновляет запись без дубликата; прокси, имя и заметки сохраняются. Можно перетащить папку или импортировать ZIP.
6. Проверить в строке аккаунта, какой прокси назначен. Не выбирать первый прокси из общего пула автоматически. В карточке прокси проверить IP, порт, протокол и данные входа с выданными провайдером. Не менять SOCKS5 на HTTP наугад.
7. «Проверить выбранные» → журнал должен содержать реальный адрес DC, номер попытки, безопасный код ошибки. Успех — ответ Telegram с user_id. Красная ошибка сети не является блокировкой аккаунта.
8. «Открыть Telegram» → дождаться автоматического подтверждения QR, при запросе ввести 2FA. Проверить, что открыт нужный аккаунт. Если автоматический вход не подтвердился, пользователь может выполнить обычный вход на странице; это нужно указать в отчёте как **ручной**, а не автоматический успех.
9. Закрыть/открыть Web повторно, проверить сохранённый вход. Проверить «Стоп» во время подключения. Не выдавать открытое окно QR за вошедший аккаунт.

Если вход всё ещё не подтверждён, вернуть безопасный отчёт: SHA, формат импорта, номер DC/адрес/порт, тип прокси, длительность, код из журнала, результат Web/DC-пробника. Не публиковать auth key/.session/TData, пароль, API hash или QR-токен. Диагностику аккаунта и прокси выполнять на ПК пользователя; серверная проверка с другого IP не равноценна.

## Интерфейс и счётчики

- Одна видимая кнопка **«Открыть…»**: стандартные диалоги Windows для файлов ZIP/.session/JSON или папки TData. Два режима внутри меню одной кнопки; собственный файловый проводник не создаётся. Также работает перетаскивание.
- В таблице прокси: название без секретов, протокол, адрес/порт, логин, состояние, назначенные аккаунты, подтверждённые блокировки. Источник и подробная причина — при выборе строки и в **«Карточке»** / двойном щелчке.
- Пароль в карточке скрыт до явного нажатия. Пароли удалены из названий, которые приходили из Dolphin. Подключение продолжает использовать оригинальные данные в vault.
- «Источник Dolphin» означает получение настроек, а не необходимость запускать браузер Dolphin. Получение ограничено 25 секундами суммарно; уже полученные прокси сохраняются при таймауте остальных профилей.
- «Назначено» — фактическое число записей аккаунтов, использующих этот прокси. «Блокировок» — записи с подтверждённым состоянием `blocked`. Счётчики нельзя обнулить, сохранив те же назначения: это исказило бы данные.
- URL смены IP провайдером не предоставлен; такая функция не выдумывалась. Приложение не переключает IP само.
- Раздел приглашений назван **«Ссылка в группу»**, чтобы не выдавать создание ссылки за массовый inviting. Импорт списков получателей, потоки массовых приглашений и рекламный комментинг не добавлялись. Для своей группы остаётся ссылка с заявкой на вступление.

## Проверки и источники

Регрессии: официальный формат сетевого блока TData, другой сохранённый endpoint, отсутствие записи в исходники, отказ первого адреса и успех второго с тем же ключом/прокси, запрет повторов при отозванной сессии, отсутствие предварительного veto, отдельная диагностика Web, скрытие паролей, реальные счётчики назначений. Windows workflow также проверяет сборку, DPAPI, протокол worker, WebView2/QR и упакованный браузер; снимки UI — артефакт Telegram-UI.

- Официальный DC/config: https://core.telegram.org/api/datacenter и https://core.telegram.org/method/help.getConfig
- Официальные сети: https://core.telegram.org/resources/cidr.txt
- Формат сетевой конфигурации: https://github.com/telegramdesktop/tdesktop/blob/dev/Telegram/SourceFiles/mtproto/mtproto_config.cpp и https://github.com/telegramdesktop/tdesktop/blob/dev/Telegram/SourceFiles/mtproto/mtproto_dc_options.cpp
- Закреплённый исходник библиотеки на ПК: `opentele/td/mtp.py` версии 1.15.1. Неподдерживаемый формат не исправлять переименованием файлов или подбором API hash.
