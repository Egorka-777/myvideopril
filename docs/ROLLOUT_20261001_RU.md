# Передача агенту ПК: 01.10.2026

## Что изменено и что не подтверждено

YouTube: кнопка «Смотреть ссылки» открывает **собственный** канал каждого выбранного профиля. Пачки до пяти профилей, старт с существующим интервалом 3–5 секунд. Следующая пачка ждёт завершения всех задач и положительного ответа Dolphin на `/stop`. При ошибке закрытия следующие профили не запускаются. Во время открытия заблокированы media/googlevideo, вызовы play и autoplay. Нет досмотра или лайков.

Источником даты служит `microformat.playerMicroformatRenderer.publishDate` в ответе YouTube. Она сравнивается с календарной датой Windows на момент запуска профиля. Это дата, предоставленная YouTube; преобразовать дату без времени в точное локальное время публикации невозможно. Надпись «N часов назад» не используется. Смотрим последние 20 карточек вкладки «Видео», не Shorts/стримы. При отсутствии подтверждённого сегодняшнего видео выдаётся ошибка; старый ролик не подставляется. При нескольких роликах за день используется порядок карточек вкладки (самая новая первой). Реальный YouTube/Dolphin на ПК ещё не проверен.

TikTok: основной режим — native Studio. Файл передаётся один раз, затем проверяется готовность формы, полная подпись из существующего банка, переключатель отложки, дата и время. Слоты — случайные интервалы 5–15 минут, **с точностью до минуты**. У HTTP beta интервалы случайные до секунды, но работоспособность приватного API не подтверждена. Первая native отложка начинается минимум через 16 минут; если время устарело во время медленной загрузки, операция останавливается до post.

Нативный адаптер поддерживает доступный переключатель radio/switch/checkbox с названием Schedule/Запланировать и видимые HTML-поля `input[type=date]`, `input[type=time]`. **Текущий календарь вашего TikTok Studio ещё не получен.** При кастомном календаре он намеренно остановится до post и сохранит список элементов и снимок. Нельзя объявлять TikTok исправленным до живой проверки. Не придумывать селекторы, координаты или схему native API по названию ошибки.

Подтверждение TikTok: принимается только фактический ответ native `/project/post/v1`, успешный код, совпадающие подпись/расписание и точный ID публикации, найденный в видимой строке Studio (для отложки — со статусом scheduled). Переход на страницу публикаций, upload video ID и наличие черновика не считаются успехом. Если endpoint/схема отличается, публикация могла состояться; повтор блокируется до сверки. Эти проверки требуют реальной сессии пользователя.

Перед post EXE сохраняет неопределённое состояние и отвечает worker через stdin `ack:<localJobId>`. Без подтверждения сохранения worker не нажимает post. Частичный успех сохраняется по каждому элементу; исключения callback больше не проглатываются. Кнопка «Ещё → Сверить загрузку» доступна в основном окне: найденную запись исключить из повтора, отсутствие подтвердить отдельно. Отмена оставляет блокировку.

HTTP beta требует локальный `webmssdk.js`, который исключён из репозитория по его прежним инструкциям. Теперь отсутствие обнаруживается до создания задания. Этот комплект не включает чужие cookies/SDK и не чинит приватный API предположениями о подписи.

## Не менять локальную установку и настройки

1. Закрыть VideoBatch. Не сбрасывать локальные изменения, не делать `git reset --hard`, не заменять `settings.xml` и не обнулять статусы попыток.
2. Создать **отдельный чистый checkout** ветки `fix/native-studio-and-open-today-20261001` репозитория `Egorka-777/myvideopril`. Все изменения локального агента сохранить в прежней папке. Не брать EXE из корня GitHub: это старый бинарник, он не соответствует исходникам.
3. Сделать резервную копию `%LocalAppData%\VideoBatchDesktop` в отдельную папку. В неё входят настройки, история, задания и диагностика. Не включать этот backup в GitHub или отчёт.
4. Из чистого checkout выполнить ровно:

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\Build-Desktop-20261001.ps1 -RuntimeDirectory 'D:\VideoBatch\VideoBatch\VideoBatch_Desktop'
```

Скрипт берёт только node.exe, node_modules, ffmpeg/ffprobe из существующего полного runtime. Все JS и модули берутся из новой ветки. Он запускает Node-проверки, собирает net48 без отсутствующего app.ico, создаёт новый полный комплект в `artifacts`, записывает SHA256 и исходный commit. Если runtime находится в другой папке, передать её точный путь; не угадывать. Нужен установленный .NET SDK.

5. Запустить только новый `artifacts\Desktop-20261001-...\VideoBatch.exe`. Старую установку не переписывать. Настройки остаются в существующем `%LocalAppData%\VideoBatchDesktop`; backup нужен для возврата к старой версии. В логе TikTok должно быть `2026-10-01-studio-schedule-evidence-v2`, YouTube — `YouTube navigation 2026-10-01`.

## Контроль YouTube

В колонку «Ссылка» каждой строки вставить собственный адрес канала, например `https://www.youtube.com/@traderprdp/videos`. Изменения сохраняются после редактирования ячейки и используются только её профилем. Кнопка остаётся «Смотреть ссылки». Нижний общий блок ссылок удалён. Поля старых общих ссылок в settings оставлены для совместимости, этот сценарий их не использует. Явный `ChannelUrl` больше не перезаписывается handle из имени. История PublishedUrl роликов остаётся в Items и не служит входом этой кнопки.

Проверить: один профиль со свежим роликом → один без сегодняшнего ролика → шесть выбранных профилей (5+1) → отмена → отказ Dolphin закрыть профиль. В первом случае увидеть свой URL и отсутствие воспроизведения, во втором — ошибку без открытия старого видео, в третьем — закрытие первых пяти перед стартом шестого. Не добавлять просмотр/лайки.

## Контроль TikTok — обязателен для завершения

1. Один профиль, один новый файл с узнаваемой подписью → «Запланировать через Studio». Не отправлять старую неизвестную попытку повторно.
2. При отсутствии поддержанного календаря: сохранить новый `diagnostics\tiktok-*.jsonl` и `*-error.png`. JSONL содержит инвентарь controls без input values/cookies. Снимок может содержать личные данные; перед передачей убрать их. Остановиться. Не переключаться автоматически на HTTP, не менять селекторы наугад.
3. Если post выполнен: найти точную запись в Studio с правильной подписью и временем. Отдельно проверить её последующее появление публично после расписания и проверки TikTok. Принятие/отложка не гарантируют прохождение модерации.
4. Только после этого проверить пять файлов, правильные разные подписи, интервалы 5–15 минут, отсутствие дублей, частичный успех и отмену после первого post.
5. Если native endpoint/структура отличаются, нужен **обезличенный** снимок структуры одного успешного ручного запроса: путь без query, ключи JSON и типы значений, названия полей даты/времени и структура ответа. Cookies, токены, X-Bogus, _signature и raw HAR не публиковать.

Сборка и mock-тесты не доказывают реальную публикацию. До этих контрольных прогонов релиз остаётся проверяемой доработкой, а не подтверждённой безошибочной версией.
