# Стили субтитров и подготовка видео перед публикацией

Обновление от 30.10.2026. База: main `422e2533c40e7e7f482a0118e70bf6ff1ae5be75`.

## Что сделано

- «Моя студия → Субтитры» открывает одно окно: превью выбранной сцены слева, карточки стилей и настройки справа. В разделе создания короткого озвученного видео кнопка «Стили» открывает то же окно.
- Семь встроенных стилей: Классика, Зелёный акцент, Жёлтый акцент, Мягкая плашка, Караоке, По одному слову, Минимализм. Настраиваются шрифт, размер, регистр, положение, число слов, цвета текста/акцента/обводки/плашки, плотность, выделение слов и лёгкое увеличение.
- «Сохранить мой стиль» сохраняет отдельный пресет в `subtitle-presets.xml` в папке данных приложения. Шаблоны сцен и настройки RU/EN/Inst/TikTok продолжают сохранять свой выбранный стиль штатным механизмом. Старые настройки совместимы.
- Предпросмотр и экспорт используют общую отрисовку. Подсветка использует реальные таймкоды слов из имеющегося ElevenLabs `.timing.json`; смена стиля не отправляет платных запросов. Пресет не хранит чужой текст или озвучку. Без таймкодов движущийся пример показывает оформление, а не выдуманную синхронизацию; прежнее требование таймкодов для экспорта сохранено.
- «YouTube/TikTok → Добавить видео»: фоновая подготовка отдельных файлов для выбранного аккаунта. Можно сразу добавлять материалы следующему. Общая очередь использует максимум два обработчика, каждый FFmpeg ограничен двумя потоками при перекодировании.
- В строке аккаунта — процент и полоса подготовки; этапы также пишутся в журнал. ПКМ по аккаунту → «Отменить подготовку видео». Готовящиеся аккаунты не передаются на публикацию раньше времени.
- Исходные файлы не переименовываются и не перезаписываются. Подготовленные находятся только в `<UploadStagingFolder>/prepared/YouTube|TikTok/<account>/`. Пачка назначается аккаунту после успешной подготовки всех файлов; при сбое/отмене её незавершённые результаты удаляются, предыдущая пачка остаётся.
- Перезаписываются встроенные метаданные: дата подготовки, программа VideoBatch, уникальный `edition_id` и, если включены в существующей обработке, пользовательские шаблоны устройств. Старые метаданные и главы удаляются. Технические свойства читаются из реального выходного файла, не выдумываются.
- Минимальная цветокоррекция: яркость в пределах ±0.001, контраст 0.999–1.001. Никаких наклонов, поворотов, пыли, шума, обрезки, зеркала, зума, изменения скорости или звука. Обычный раздел обработки не меняется.
- Цветокоррекцию можно отключить через «Ещё» (в TikTok также через ПКМ). Тогда меняются только метаданные, видеодорожка копируется без перекодирования. HDR всегда идёт этим путём, чтобы не менять цвет.

Изменение метаданных создаёт разные файлы, но не гарантирует, что платформа посчитает одинаковое содержимое разными произведениями.

## Установка агенту на ПК

1. Закрыть VideoBatch. Проверить путь именно того EXE, который запускает ярлык. Настройки, профили, файлы озвучки, материалы и историю не удалять.
2. Подтянуть актуальный main обычным `git pull --ff-only`. При локальных правках сначала сохранить их, не применять `reset --hard`.
3. Собрать: `dotnet build VideoBatch.csproj -c Release -p:ApplicationIcon=`.
4. Использовать **`bin/Release/net48/VideoBatch.exe`**, а не исторический EXE из корня репозитория. Обновить EXE, его config и соседние DLL штатным комплектом, сохранив существующие ffmpeg/ffprobe, Node, tools/uploader и данные. Для этого обновления JS загрузчика не менялся.
5. При использовании готового артефакта `VideoBatch-Subtitle-Upload-Update` скопировать его содержимое в фактическую папку приложения, сохранив существующие инструменты и данные. Это обновление установленного комплекта, не новый portable-архив.
6. Запустить приложение и выполнить проверки ниже. Не менять селекторы публикации и подключение Dolphin в рамках этой установки.

## Проверка на ПК

1. В студии выбрать озвучку с таймкодами, открыть «Субтитры», выбрать зелёный акцент, затем караоке. Убедиться, что пример движется; поменять цвета/положение, сохранить свой стиль. После перезапуска он должен остаться в галерее, а стиль вкладки — в своём шаблоне.
2. Экспортировать один короткий ролик. Проверить подсветку слов по озвучке, положение/цвета и отсутствие лишних субтитров за пределами фразы. Верхний заголовок остаётся отдельным объектом сцены.
3. В публикациях добавить один исходник к трём аккаунтам подряд, включая TikTok. Интерфейс должен оставаться доступным, максимум два задания обрабатываются, третье ждёт. Должны быть проценты и журнал.
4. Проверить, что каждому назначен свой подготовленный файл, исходник не изменился, продолжительность/размер/звук сохранились. Сравнивать метаданные через ffprobe, а не только свойства Проводника.
5. Начать ещё одну подготовку и отменить через ПКМ. Старые назначенные видео должны сохраниться; недописанного `.preparing-*.mp4` быть не должно.
6. Отключить цветокоррекцию и повторить добавление: меняются только метаданные, без эффектов и перекодирования. Удаление уже готовых и ранее использованных файлов агент автоматически не выполняет.

## Автопроверки

Workflow: `.github/workflows/subtitle-upload-preparation.yml`.

- Полная сборка desktop net48 на Windows.
- `SubtitleUploadTests.RunSelfTests`: совместимость старого XML, встроенные/свои стили, реальные таймкоды, подсветка/увеличение, рендер, строгие пределы эффектов.
- `RunIntegrationTests`: настоящие FFmpeg/ffprobe, три параллельных запроса через очередь из двух обработчиков, разные метаданные, неизменный исходник, исходные размеры/длительность/звук, побайтовая идентичность видеодорожки при remux, очистка неудачной пачки и отмена.
- Регрессионные проверки существующей обработки, изоляции профилей и озвученного видео.
- `RunUiTests`: скриншоты реального Windows-окна для каждого стиля; артефакт `Subtitle-Preset-Screenshots`.

Публикация в живые аккаунты не требуется для этих тестов и автоматически не выполняется.
