# VideoBatch: обновление в Cursor на Windows

Ветка обновления: `fix/tiktok-caption-watch-completeness-20260921`. Изменения исходного приложения применяются к существующему VideoBatch; отдельное приложение не создаётся. Профили и прокси остаются в Dolphin. Живой тест выполняет владелец ПК вручную.

## Задание для Cursor

> Работай с `D:\VideoBatch\repo`, не запускай Dolphin, TikTok Studio, YouTube Studio или загрузку видео из Cursor. Перед изменениями покажи `git status --short`, `git branch --show-current` и `git log -1 --oneline`. Сохрани незакоммиченные изменения: если рабочая копия грязная, создай новую отдельную рабочую папку через `git worktree add`, без `git reset --hard`, `git clean` и перезаписи настроек. Подтяни ветку `fix/tiktok-caption-watch-completeness-20260921` из `origin` и переключись на неё в чистой копии. Выполни `npm ci --prefix tools/uploader --ignore-scripts`, `node tests/tiktok_caption_regressions.js`, `node tests/watch_plan_regressions.js`, `node tests/watch_regressions.js`, затем `dotnet build VideoBatch.csproj -c Release -p:ApplicationIcon=` (файл `app.ico` может существовать только в рабочем комплекте на ПК). Если сборка не проходит, пришли полный вывод компилятора и остановись; не исправляй наугад. Выполни `powershell -NoProfile -ExecutionPolicy Bypass -File scripts\Build-AsphaltTest.ps1` в этой копии. Убедись, что `artifacts\asphalt-test\VideoBatch.AsphaltTest.exe` существует и рядом есть `tools\uploader\node.exe`, `worker.js`, `worker-tiktok.js`, `node_modules\playwright-core`. Если пакет недостаёт, сообщи какой именно; не запускай живой тест. Рабочий `settings.xml`, каталог профилей Dolphin, очередь и исходное приложение не переписывай. Сообщи абсолютный путь к готовому EXE, хеш коммита, результат каждого теста и сборки. Живой тест я запущу сам.

## Что изменилось

1. В TikTok одна база многострочных подписей вместо двух полей. Кнопка «Подписи» открывает редактор: между шаблонами ставится отдельная строка `---`. Для RU при первом запуске создаются десять вариантов с неизменной строкой хэштегов. Старые банки заголовков и описаний сохраняются в `settings.xml`.
2. При добавлении пачки подписи распределяются по кругу; подтверждённые TikTok ролики помечаются и повторно автоматически не загружаются. Публикация идёт последовательно, один профиль за раз по умолчанию. TikTok должен подтвердить результат; при неизвестном результате профиль остаётся открытым для проверки вручную.
3. Сетка YouTube получает все ролики из текущего каталога, различает длинные видео и Shorts, не обрывает канал через 28 минут. Сбой ролика отражается в итоге канала; успешно просмотренные ролики пропускаются при повторной попытке этого канала в текущем запуске. Один профиль просмотра работает за раз по умолчанию.
4. Сохранение `settings.xml` защищено общим замком и уникальными временными файлами, чтобы параллельные операции не конфликтовали из-за одного `.tmp`.

## Проверка владельцем ПК после сборки

1. Сделайте копию `%LOCALAPPDATA%\VideoBatchDesktop\settings.xml` и рабочей папки приложения. Убедитесь, что VPN, Dolphin и прокси работают в обычном для вас режиме.
2. Откройте новый EXE вручную. В TikTok проверьте «Подписи»: их 10, каждая содержит полный текст и тот же набор хэштегов. Выберите **один тестовый аккаунт и один ролик**; убедитесь, что поле подписи заполнено целиком и публикация действительно появилась в TikTok. Не запускайте вторую попытку, пока не проверили итог первой.
3. После успешного теста проверьте пачку из двух роликов на том же аккаунте. Если второй упадёт, отметка первого должна сохраниться: после проверки вручную следующий запуск берёт только оставшийся. При неизвестном итоге второго проверьте TikTok Studio перед повтором.
4. Для просмотра запустите сетку на двух собственных тестовых профилях и канале с несколькими длинными роликами и Shorts. Сверьте журнал «план: длинных N, шортсов M» с итогом и фактическим воспроизведением. Ошибка или недосмотр должны показать неуспешный канал, а не «готово».
5. Приложите лог окна, `%LOCALAPPDATA%\VideoBatchDesktop\diagnostics\` и время запуска, если результат отличается. Файлы диагностики могут содержать идентификаторы аккаунтов; секреты и cookies перед передачей удалите.

### Ограничения проверки

Node-регрессии и сборка проверяют код, но не подтверждают живую публикацию или просмотры на конкретных аккаунтах. Старые уже опубликованные TikTok видео невозможно распознать автоматически по локальной папке; сначала проверьте открытые ранее пачки. Режим прямой HTTP-публикации TikTok здесь не добавлен: работающий вариант YouTube не переносится на другую платформу одним переключателем.
