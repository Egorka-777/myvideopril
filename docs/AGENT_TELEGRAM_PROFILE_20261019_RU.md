## Как пользоваться

1. Telegram → выделить один аккаунт → **Изменить данные**. То же действие есть в меню правой кнопки мыши.
2. Выбрать сохранённый шаблон или **＋ Новый**. Задать название шаблона, имя и фамилию. Прикрепить PNG/JPG через **Выбрать фото**. Предпросмотр показывает квадрат по центру исходника, который отправится в Telegram.
3. **Сохранить шаблон** сохраняет его для следующих запусков и ничего не меняет в Telegram.
4. **Применить к аккаунту** сохраняет шаблон, закрывает окно настройки и запускает изменение выбранного аккаунта. Прогресс и **Остановить** находятся в основном окне приложения.
5. Успех показывается только после повторного чтения имени/фамилии и ID фотографии с Telegram. Уже открытое рабочее веб-окно этого аккаунта обновляется один раз после подтверждения.

Пустая фамилия означает удаление прежней фамилии. **Без замены фото** оставляет действующую аватарку. Картинка и данные шаблона сохраняются; исходный файл можно убрать из папки загрузок. Повторное применение уже подтверждённого фото не создаёт новую аватарку, пока её ID в Telegram совпадает с сохранённым. Если аватарку меняли вне приложения, она загружается заново согласно выбранному шаблону.

Используется действующая импортированная сессия и тот же назначенный прокси. Новые API ID/hash вводить не нужно. Это официальные `account.updateProfile` и `photos.uploadProfilePhoto`, а не клики по случайным элементам Web UI. Поля bio, username, пароль и номер телефона эта функция не меняет. Массовых действий, сообщений и приглашений здесь нет.

## Установка агентом

Использовать успешный `Telegram workspace` **этой ветки**, артефакт **Telegram-Profile-Update**. В нём EXE, DLL, WebView2 runtimes, tools/telegram и tools/uploader. Обновлять их вместе. Это общий комплект обеих доработок; не нужно устанавливать более старый YouTube EXE поверх нового Telegram EXE.

1. Проверить фактическую папку запуска приложения. Сохранить копию её файлов и `%LOCALAPPDATA%\VideoBatchDesktop`. Закрыть VideoBatch и его workers; не удалять аккаунты, `telegram.vault`, резервные копии и папку `telegram\web`.
2. Получить ветку без перезаписи локальных изменений. При необходимости создать отдельный checkout:

```powershell
git fetch origin feat/telegram-profile-templates-20261019
git worktree add ..\repo-telegram-templates origin/feat/telegram-profile-templates-20261019
```

3. Установить общий комплект из успешного CI либо собрать EXE из нового checkout. Скопировать EXE/DLL/runtimes и соответствующие tools вместе, проверить SOURCE_COMMIT.txt. Для исходной сборки:

```powershell
npm ci --prefix tools/uploader --ignore-scripts
dotnet build VideoBatch.csproj -c Release -p:ApplicationIcon=
```

При установке артефакта выполнить npm ci из **папки установленного приложения**, поскольку node_modules в ZIP не входят. Не заменять только EXE или один Python-файл.

4. Из папки установленного приложения:

```powershell
npm ci --prefix tools/uploader --ignore-scripts
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\tools\telegram\doctor.ps1 -AppRoot (Get-Location).Path -Repair
```

Ожидаются package/runtime=ready, exit_code=0 и версия Telegram v6. Doctor восстанавливает компоненты, не изменяя профили аккаунтов. Telegram с рабочей сессией не переимпортировать. Нужен Python 3.11 x64; setup зависимостей требует интернет.

## Проверки и ограничения

- Локальные тесты профиля используют подставные RPC: правильный аккаунт, имя/фамилия, очистка фамилии на уровне TL-флагов, фото, повтор без дублирования, изменённая внешне аватарка, неверные файлы до соединения, FloodWait, отмена и частичный сбой.
- Windows CI проверяет зашифрованное хранилище и восстановление шаблона, сохранность аккаунтов/прокси/исходной картинки, одинаковый квадрат в preview/файле, отсутствие дублей локальных фото и границы элементов формы. Отдельно проверяется прежняя цепочка WebView2/WSS/QR, runtime repair и запуск из упакованного комплекта.
- Workflow Studio запускается и для этой ветки: EXE/C# и браузерные проверки RU/EN, превью и расписания.
- Для живой приёмки применить один явно выбранный шаблон к одному тестовому аккаунту. Реальные учётные данные здесь отсутствуют; успешный fake RPC-тест не является доказательством изменения настоящего аккаунта.

Имя и фото — две отдельные операции Telegram; атомарного общего сохранения нет. Если имя сохранилось, а фото получило ошибку/неопределённый ответ, приложение сообщает о возможном частичном изменении. Автоматических повторов записи нет. Сначала посмотреть реальный профиль и журнал, затем решать, повторять ли. FloodWait сохраняется как пауза; другая сессия/прокси не подставляется.

Шаблоны хранятся в существующем зашифрованном `telegram.vault`; нормализованные фото — в `telegram\profile-avatars` внутри каталога с прежними Windows ACL. Файлы изображений сами по себе не зашифрованы. Взять в резервную копию весь каталог Telegram. Старые фото шаблонов автоматически не удаляются, чтобы не сломать ссылки в резервном vault. Секреты, пользовательские скриншоты и фото не коммитить.

Официальные методы:
- https://core.telegram.org/method/account.updateProfile
- https://core.telegram.org/method/photos.uploadProfilePhoto
