# Открытие видео сеткой: инструкция агенту ПК

Результат: отмеченные профили выбранного рынка открывают ссылки каналов из таблицы; на каждом канале выбирается последнее подтверждённое сегодняшнее обычное видео. Каждый профиль проходит все выбранные каналы, включая свой. Пачки до пяти. Следующая пачка начинается только после завершения задач и подтверждения Dolphin о закрытии текущих профилей. Первая ссылка меняется циклическим сдвигом; набор ссылок одинаковый.

## Подтверждённые причины прежнего сбоя

В ветке `fix/youtube-mesh-crosswatch-20261001`, коммит `496a6cf`:

1. Пачка вычислялась из `WatchMaxParallelProfiles`; в присланном settings.xml стоит 4. Пятый профиль попадал во вторую пачку. Это не доказательство сбоя запуска пятого профиля.
2. Вместо сегодняшней публикации выбирались ID из истории Published URL. Присланный каталог содержит 59 записей RU/EN без даты публикации. Код требовал найти эти ID на вкладке «Видео».
3. В логе канал успешно подтверждён, затем поиск сохранённых ID завершается ошибкой и повторяется. Лог не доказывает, что ролики private или отложены: эта фраза была предположением обработчика ошибок. В логе нет DOM страницы, поэтому точную причину отсутствия карточек старых ID установить нельзя.
4. Для обычного видео существовали обходы через Shorts и проверка минимальной длительности. Нынешняя сетка получает кандидатов только из обычных карточек вкладки /videos, проверяет владельца и дату по метаданным и отклоняет Shorts-плеер. Короткая длительность сама по себе не делает обычный ролик Shorts.

## Что проверить в новой версии

- Поля «Ссылка» сохраняются после редактирования; явные ссылки имеют приоритет перед handle из имени. Прежний каталог публикаций не используется этой кнопкой.
- «Смотреть ссылки» использует отмеченные аккаунты текущей вкладки. «Смотреть RU» использует отмеченные RU-аккаунты, в том числе при открытой вкладке EN.
- Названия вкладок интерфейса YouTube на русском/английском не служат фильтром даты. Используется publishDate и точный channelId. Если publishDate содержит время и часовой пояс, дата пересчитывается по текущему смещению Windows; дата без времени сравнивается как дата, предоставленная YouTube.
- Источником порядка служит порядок обычных карточек на вкладке «Видео». Проверяются первые 20 кандидатов. Старое видео не подставляется при отсутствии сегодняшнего, неизвестной дате или неподтверждённом владельце.
- Канал имеет общий бюджет навигации 90 секунд. В логе видны этапы, ID кандидата, дата и результат, а не молчаливое ожидание длительности.
- При ошибке одного канала оставшиеся ссылки продолжают обрабатываться. Вся операция для профиля не получает успех, если хотя бы один канал не подтверждён. При отмене C# закрывает активные профили. Закрытие принадлежит одному компоненту; worker не делает второй stop для этой сетки.

## Сборка и запуск

1. Сохранить прежнюю установку, локальные изменения и резервную копию `%LocalAppData%\VideoBatchDesktop`. Не копировать настройки в GitHub.
2. В отдельной папке взять ветку этой доработки. Не использовать EXE из корня репозитория и не смешивать worker-файлы разных версий.
3. Из новой папки выполнить:

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\Build-Desktop-20261001.ps1 -RuntimeDirectory 'D:\VideoBatch\VideoBatch\VideoBatch_Desktop'
```

Если полный runtime находится в другой папке, использовать его фактический путь. Скрипт собирает новый комплект, запускает Node и C# проверки и записывает исходный commit/SHA256. Выходную папку не накладывать на старую. Ссылку на новую ветку и точный commit взять из PR этой доработки.

4. Запустить EXE из новой папки `artifacts\Desktop-20261001-...`. При «Смотреть ссылки» worker сообщает `YouTube navigation 2026-10-01-paused-grid`. Проверить SOURCE_COMMIT.txt и SHA256_MANIFEST.txt.

## Приёмка на ПК

1. Один отмеченный профиль с сегодняшним обычным видео: кнопка теперь работает и для одного канала; открыть свою ссылку и проверить выбранный ролик.
2. Два профиля: оба проходят обе ссылки. Проверить журнал URL; на каждом канале должен открываться выбранный ролик.
3. Шесть профилей: пачки 5+1. В логе перед второй пачкой должно быть подтверждение закрытия первой. Число одновременно открытых выбранных профилей не превышает пяти.
4. На EN-вкладке нажать «Смотреть RU»: запускаются только сохранённые отмеченные RU-профили. Затем отдельно проверить обычную кнопку на EN.
5. Канал без сегодняшнего видео и канал с Shorts: обычный вчерашний ролик/Shorts не подставляются. Ошибка указывается, остальные ссылки обрабатываются.
6. Нажать «Стоп» во время активной пачки. Проверить закрытие профилей и отсутствие новой пачки.
7. На тестовом запуске имитировать отказ закрытия Dolphin: ошибка закрытия должна блокировать следующий запуск. Не обходить подтверждение закрытия.

Браузерные тесты используют локальные страницы с интерфейсом RU/EN и метаданными YouTube; они проверяют выбор, исключение Shorts, игнорирование старого каталога и частичные ошибки. Проверка в реальных авторизованных профилях Dolphin проводится только на ПК. Успешная сборка не является подтверждением этого прогона.

При ошибке каналов приложение сохраняет `diagnostics\youtube-navigation-*.json` и `.png`, пути пишет в текущий лог. JSON содержит ID канала/плеера, количество обычных карточек, ID кандидатов и состояние плеера; HTML, cookies, токены и значения форм не сохраняются. Снимок может содержать данные аккаунта — перед передачей их убрать.

Если реальный профиль показывает ошибку, агент сначала читает текущий лог и эти файлы. Снимок от пользователя нужен только если автоматически сохранённый снимок недоступен. Не исправлять одновременно URL, селекторы и настройки без установленной причины; не подставлять другой ролик и не скрывать частичный сбой сообщением об успехе.

Карточки извлекаются из данных выбранной вкладки: `videoRenderer` и `lockupViewModel` с типом `LOCKUP_CONTENT_TYPE_VIDEO`; полки Shorts исключаются. Для прежней разметки сохранён поиск обычных карточек. Браузерная проверка покрывает оба варианта. Открытие каналов не ждёт внешние сервисы IP; отдельная проверка профиля и загрузки сохраняют прежнее поведение.
