## Что подтверждено по коду

Очередь TikTok уже последовательная: C# ограничивает одновременно работающие профили одним, а worker выполняет `await uploadOne(...)` для каждого видео. Полный цикл первого заканчивается до начала второго. Эта очередь сохранена. После тайм-аута модерации подтверждённая запись может остаться «На проверке»; повтор не создаётся, следующий файл может обрабатываться дальше.

Ввод подписи был клавиатурным, но с задержкой 10 мс между символами. Теперь задержка 70 мс. После выбора файла приложение ждёт готовности загрузки и обеспечивает минимум 15 секунд от выбора файла до ввода подписи. Если загрузка заняла дольше, дополнительное ожидание до 15 секунд уже не нужно. Повторная проверка совпадающей подписи её заново не печатает. Банки RU/EN и запрет повторов сохранены.

В цепочке YouTube исправлены обнаруженные ограничения:

- `NativeStudio.open()` ожидал Go live/End stream до получения ключа и старта FFmpeg. Если Studio не показывает кнопку запуска до появления видеосигнала, цепочка останавливалась. Теперь достаточно готовности самой комнаты: настройки/URL сервера доступны, даже когда Go live ещё отсутствует. Запуск остаётся отдельным действием после готовности сигнала.
- Поиск промежуточного Create new включал общее русское «Создать», которое могло совпасть с глобальной кнопкой Studio. Общее «Создать» исключено из этого поиска.
- Финальная кнопка мастера ожидалась только как Schedule stream. Добавлены Done / «Готово».
- До создания события проверяются доступ к эфирам и начальная настройка «Позже → Видеокодер». При обнаружении активации/проверки доступа приложение сообщает причину; не пытается обходить проверку YouTube. Неизвестный вариант экрана также останавливается с диагностикой.
- Копирование ключа поддерживает нативные `clipboard.writeText`, `clipboard.write` и `execCommand('copy')`. Ключ перехватывается в рабочей вкладке, не записывается в системный буфер обмена или журнал операции и удаляется из временных переменных страницы.
- Ошибки до запуска менеджера и этапы worker раньше не попадали в общий лог эфира. Теперь лог начинается с первого нажатия, содержит выбранный канал/профиль, runtime, подключение Dolphin, проверку канала, настройку Studio, создание события, получение ключа, метаданные и запуск FFmpeg. Ошибки видны в журнале, а проблемная вкладка остаётся открытой.

Это подтверждённые проблемы реализации и исправления. По одному скриншоту нельзя установить, какая из них остановила конкретную попытку пользователя. На скриншоте виден URL сервера, но ключ и исходная ошибка не показаны. Сквозная проверка на реальном канале остаётся обязательной.

1. Закрой приложение после остановки текущих загрузок/эфиров. Сохрани резервную копию установленной папки и пользовательских данных.
2. Обнови из указанной ветки. Не удаляй настройки, аккаунты, прокси, профили Dolphin, материалы, историю комбинаций/публикаций, шаблоны и журналы эфиров. Не сбрасывай runtime к старому архиву поверх новой сборки.
3. Установи новый EXE, `.exe.config` и **актуальные worker JS** вместе. Обновление только EXE недостаточно: добавлена операция `prepare` и сообщения этапов, которые старый worker не понимает.

## Проверка YouTube

- Выдели строку нужного канала; галочки других строк не определяют канал эфира.
- У строки должны быть её Dolphin Profile ID и корректная ссылка канала или сохранённый подтверждённый YouTube ID. Программа сверяет точный канал; не подменяй его текущим случайным каналом профиля.
- Нажми «Запустить эфир», выбери папку, параметры и нажми запуск. Лог должен появиться сразу, ещё до обращения к Dolphin.
- Кнопка «Открыть лог» находится в окне эфира. После его закрытия: правая кнопка по строке канала → «Открыть лог эфиров». Файл `youtube-live.log` находится в каталоге пользовательских данных приложения; путь не нужно угадывать — кнопка откроет фактический файл.
- В логе должна быть строка worker **20261014-live-setup-v1**. Её отсутствие при проверке сессии означает, что до нового worker не дошли: смотри предыдущую ошибку/строку Runtime. Если запускается старый worker, обнови всю рабочую папку загрузчика, которую показывает Runtime.
- В первый раз Studio может попросить активацию трансляций. Это зависит от канала. Программа сообщает об этом; первый доступ YouTube может активироваться до 24 часов. Не указывай пользователю, что API-токен Dolphin — это ключ YouTube: это разные данные.
- Для передачи из ПК используются URL сервера и **ключ трансляции**, как в OBS/VLC. Логин/пароль видеокодеру не передаётся; вход в сам YouTube берётся из сессии Dolphin. Программа получает ключ выбранного события автоматически и передаёт локальному FFmpeg по RTMPS.
- Убедись, что FFmpeg появился, Studio увидел видеосигнал, эфир стал активным, название/превью сохранены и остановка завершает нужный канал.
- Если ошибка повторилась, проблемная вкладка должна остаться открытой. Диагностический JSON находится в `live-session/<operationId>.diagnostic.json` внутри каталога данных; его путь выводится в лог. Он содержит команду, последний шаг/локатор, ошибку и пути/коды запросов без cookies и ключа.
- Не удаляй старые `youtube-live` журналы, lease-файлы и записи о незавершённых запусках для «лечения». Они защищают от двойного эфира. Сначала проверь прежнее событие и завершение в Studio.

## Проверка TikTok

На одном своём профиле выбери несколько тестовых файлов. Они должны обрабатываться последовательно. Дождись готовности файла, затем наблюдай подпись: удаляется исходное имя, текст печатается постепенно и совпадает с банком RU/EN. После первого подтверждённого поста начинается следующий файл; уже опубликованный или находящийся на проверке ролик не загружается повторно.
