# Агенту на ПК: отдельный раздел Telegram

Репозиторий `Egorka-777/myvideopril`. Ветка **`feat/telegram-workspace-20261015`**.
Основа — `main` на коммите `a2729a2`, с последней доработкой YouTube Studio. В main эту задачу не сливать автоматически.

## Что установить

1. Закрой приложение. Сохрани резерв установленной папки и `%LOCALAPPDATA%\VideoBatchDesktop`. Не удаляй настройки, аккаунты, шаблоны, историю сборок, Dolphin, Node, FFmpeg и модели Нарезчика.
2. Не переключай действующую рабочую папку поверх несохранённых правок. Подготовь отдельную:

```powershell
git clone --branch feat/telegram-workspace-20261015 --single-branch https://github.com/Egorka-777/myvideopril.git myvideopril-telegram
cd myvideopril-telegram
dotnet build VideoBatch.csproj -c Release -p:ApplicationIcon=
```

3. Перенеси новый `VideoBatch.exe` и его config в установку. Рядом обязательна полная папка **tools/telegram** из ветки: worker.py, requirements.txt, setup.ps1. Также обнови JS/package-файлы tools/uploader из ветки, чтобы сохранить совместимость EXE с уже включённой Studio-доработкой. Существующие node.exe/node_modules оставь; при изменении lock выполни npm ci. Не заменяй папки пользовательских данных чистыми папками из репозитория.
4. Установи **Python 3.11 x64 с Python Launcher**. Разделу Telegram не нужны Whisper, Ollama или платная подписка. В приложении: **Telegram → Настройки → Подготовить Telegram**, либо:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\telegram\setup.ps1
```

   Скрипт создаёт собственное окружение `%LOCALAPPDATA%\VideoBatchDesktop\telegram\venv`. Не ставить зависимости в окружение Нарезчика. Используется Telethon 1.45.0; **python-socks обязателен**, иначе эта версия Telethon может игнорировать прокси. Скрипт и требования уже включают эту зависимость. Для TData используются opentele/PyQt5; установлены совместимые Windows-бинарные зависимости. Подготовка требует интернета.
5. В логах worker должна быть версия `2026-10-15-telegram-v1`.

## Что работает

- Отдельный **Telegram** в основном меню, в существующей асфальтовой теме. Внутри три вкладки: Аккаунты / Приглашения / Журнал.
- Импорт `.session` с парным одноимённым `.json`, папки TData, ZIP с несколькими такими аккаунтами. Можно перетащить файлы на раздел. JSON должен относиться к Telethon SQLite-сессии, а не к произвольному формату другого клиента.
- Если в парном JSON нет `api_id`/`api_hash` (также понимаются `app_id`/`app_hash`), один раз ввести свою пару в настройках приложения. Получить на https://my.telegram.org. Пустые API не подменяются случайными/чужими значениями. API, модель/версия клиента и язык из JSON сохраняются для аккаунта. Нет случайной смены отпечатков устройств.
- TData читается локально, в том числе с локальным кодом-паролем. Берутся все аккаунты из TData. Поддержан текущий формат opentele 1.15.1; совместимость с любой будущей версией Telegram Desktop не заявляется. Неверный пароль/повреждение дают ошибку импорта. Код-пароль не сохраняется.
- Импорт сам **не подключается к Telegram** и не завершает чужие/другие сессии. Исходные .session/TData остаются без изменений. Для .session в этой версии допускаются известные production DC IPv4 и порт 443; нестандартная DC/test/IPv6-сессия требует отдельной поддержки, а не скрытой подмены.
- Дедупликация одинаковых ключей при повторном импорте: существующая карточка с назначенным прокси не стирается. После «Проверить» имя, username и телефон читаются из Telegram.
- Двойной клик по аккаунту → карточка: имя, прокси, страна, заметка, состояние. Есть выбор прокси из сохранённых карточек общего раздела «Аккаунты», если там записаны **полные** адреса прокси. IP из Dolphin-профиля не является полным прокси: порт/логин/пароль не угадываются. Если полных значений нет, вставить вручную. Не объявлять, что все прокси подтянулись, без проверки.
- Форматы прокси: `socks5://login:password@host:port`, `socks4://...`, `http://...`, `host:port:login:password` (SOCKS5), `host:port`. Символы @/: в credentials лучше URL-кодировать. Один назначенный прокси на аккаунт. Пустой прокси означает прямое соединение. **При ошибке настроенного прокси прямого обходного соединения нет.**
- Отдельные статусы «Работает», «Нет связи», «Нужен вход», «Заблокирован», «Ожидание Telegram», «Ограничен», «Нужна настройка». Ошибка сети не считается блокировкой. Сам импорт не означает «аккаунт работает».
- Правый клик → удалить именно текущую карточку только из Telegram-раздела. Telegram-сессия на сервере не отзывается, исходники сохраняются.
- «Прогрев» **в этой версии означает проверку соединения и чтение до 20 доступных диалогов**, без сообщений, реакций, отметок прочтения, накрутки просмотров и случайной активности. Это не реализация «хаотичных действий» со скриншотов и не гарантия защиты от бана. Не описывать её пользователю иначе.

## Приглашения

1. В «Аккаунты» выбрать **ровно один** аккаунт галочкой (без галочек используется выделенная строка). Многопрофильные волны/ротация из примера сейчас не реализованы.
2. «Приглашения»: указать **существующую** вашу супергруппу/канал: @username, публичную t.me-ссылку либо известный ID. Для приватного ID приложение ищет существующий диалог среди первых 100. Вступления по приватной invite-ссылке и создания канала из шаблона в этой версии нет.
3. Вставить @username пользователей, по одному на строку или через запятую. Нужны права владельца/администратора приглашать в выбранную группу/канал. Обычные старые чаты не поддержаны. Списки не парсятся/не собираются из чужих групп.
4. Задать **фиксированную** паузу 10–3600 сек, нажать Запустить. Подтвердить конкретный аккаунт и группу. Система не обещает, что выбранный интервал разрешён Telegram: фактические ограничения сервера имеют приоритет.
5. Пользователи обрабатываются по одному. Результат RPC сам по себе не считается успехом: дополнительно проверяется членство. `missing_invitees` показываются как недобавленные. Приватность пользователя не обходится.
6. При FloodWait/PeerFlood/потере связи задача останавливается целиком. Никакой смены аккаунта/прокси для продолжения. Длительность FloodWait сохраняется в карточке; повторные приглашения до её окончания не запускаются.
7. **До запроса** на диск записывается пара ID группы + ID пользователя. Успешная, неопределённая либо прерванная попытка не пересылается автоматически, в том числе от другого аккаунта и после перезапуска. Не стирать `invites.sqlite` ради повторного прогона; после неопределённого результата сначала проверить членство вручную.
8. «Остановить» прерывает ожидание; если библиотека зависла на сетевом вызове, процесс завершается после 5 сек. Незавершённая запись остаётся для ручной проверки. При закрытии приложения worker останавливается.

## Данные и диагностика

- Сессии/API/прокси хранятся в **telegram/telegram.vault**, зашифрованы Windows DPAPI для текущего пользователя. Атомарная запись с .bak; повреждённое/чужое хранилище не перезаписывается. Резерв переносится вместе с Windows-учётной записью/её ключами; обычное копирование vault на другой ПК не расшифрует его.
- На Telegram-папку ставится доступ текущего пользователя Windows и SYSTEM. Рабочие JSON с auth_key на диск не записываются; секреты передаются worker через stdin. Для ZIP создаётся временная распаковка внутри защищённой папки; после импорта удаляется. Остатки после аварийного закрытия чистятся при следующем запуске worker. Исходный ZIP/.session/TData вне приложения остаётся под ответственностью владельца.
- ZIP ограничен 256 МБ/10 000 файлов; path traversal, симлинки, дублирующие имена и вложенные ZIP отклоняются. Распаковка не исполняет программы из архива.
- История приглашений `invites.sqlite`, статусы/настройки — постоянные. Журнал внутри раздела показывает текущий запуск; прошлые логи доступны через «Открыть логи» и общий раздел «Логи» с фильтром **Telegram**. Задачи появляются в общем разделе «Задачи».
- В общие логи **не передавать raw worker JSON, session, api_hash, пароли прокси или полный JSON импорта**. Уже существующий callback импортированных аккаунтов специально не пишет payload в журнал.

## Обязательная проверка на ПК

Автотесты используют синтетические ключи и подменённые RPC, а не настоящий Telegram-аккаунт. Проверка реального входа/прав/инвайта на ПК нужна до массовой работы.

1. Начать с собственного тестового аккаунта: импорт .session+JSON, проверить исходный hash файла до/после. Повторный импорт не создаёт дубль.
2. Назначить рабочий прокси, проверить карточку. Затем временно поставить недоступный порт: должен быть «Нет связи», без прямого обхода и без «Заблокирован». Вернуть правильный прокси.
3. Проверить TData, при наличии — с локальным паролем; неверный пароль должен показать понятную ошибку, без потери других импортов.
4. Создать/использовать свою тестовую супергруппу и тестового пользователя, согласного вступить. Один реальный инвайт, затем вручную проверить членство. Повторить запуск/перезапустить приложение: повтор не должен уйти.
5. Проверить отмену между пользователями и закрытие программы. После рестарта история и карточки сохранены. Не провоцировать FloodWait на реальных аккаунтах ради теста — это уже покрыто фикстурой.
6. Проверить, что YouTube Studio/TikTok/Нарезчик открываются как раньше. Не удалять общие данные для устранения ошибки Telegram.

## Тесты и ограничения

Workflow **Telegram workspace** собирает Windows .NET 4.8, готовит настоящий Python 3.11 Windows-runtime, проверяет DPAPI/порчу хранилища, сериализацию, навигацию, UI-снимки, существующие Studio/аккаунт/планировщик/JS-регрессии. Python-тесты: реальный SQLite/TData roundtrip офлайн (с парольной TData), ZIP, запрет сети при импорте, настоящий локальный SOCKS5 handshake, последовательная очередь, проверка членства, missing_invitees, FloodWait, аварийный pending, неопределённый ответ, повтор после перезапуска, отмена, read-only прогрев.

В этой версии нет магазина аккаунтов/прокси, автоматической покупки, 2FA/сброса других сессий, парсинга аудитории, массовых рассылок, антибан-обещаний, создания каналов, имитации случайной активности. Это не копия всех пунктов меню стороннего приложения на скриншотах.
