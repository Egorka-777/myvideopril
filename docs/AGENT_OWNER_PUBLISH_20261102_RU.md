# YouTube: открытый доступ и комментарий автора

В main исправлена отдельная кнопка «Опубликовать» для ранее загруженных роликов. Рабочая загрузка через Studio, её заголовки, описания и расписание не переделывались.

## Что исправлено

- «Отложенная публикация», сокращённое «Отложенная публ…» и «Для всех» распознаются наряду с Scheduled / Public. Незнакомая надпись сама по себе больше не блокирует открытие настроек доступа.
- В окне доступа раскрывается «Сохранить или опубликовать / Save or publish», выбирается «Открытый доступ / Public», затем один раз нажимается «Опубликовать / Publish». Сохранён вариант Studio с «Готово / Done» и отдельным «Сохранить / Save» в редакторе.
- После сохранения проверяется открытый доступ этого же ролика. Затем открывается его страница YouTube и отправляется сохранённый комментарий автора. Выбор ролика идёт по уже сохранённому ID, а не по случайной первой строке списка.
- Сохранённые подписи аккаунтов не удаляются и не перезаписываются. При подготовке публикации в ссылках Telegram `start=t0211` / `start=i2110` обновляются только последние четыре цифры дня и месяца. Префикс `t` / `i`, остальной текст и ссылки сохраняются. Поддерживаются и явные `{ddMM}`, `{dd}`, `{MM}`, `{yyyy}`, `{date}`.
- Дата берётся с ПК. Уже отправленные комментарии не редактируются. Подтверждённый комментарий не дублируется при повторном запуске; неподтверждённая отправка остаётся на ручной проверке.

В журнале отдельный маркер этого модуля: **2026-11-02-owner-publish-public-v1**. Общий BUILD загрузчика остаётся **2026-10-23-studio-two-profiles-v21**: рабочую цепочку загрузки не меняли.

## Установка агентом на ПК

1. Остановить задания и закрыть VideoBatch. Сохранить текущие незакоммиченные изменения, если они есть.
2. В рабочем клоне выполнить:

   ```powershell
   git fetch origin main
   git switch main
   git pull --ff-only origin main
   dotnet build VideoBatch.csproj -c Release -p:ApplicationIcon=
   .\scripts\Sync-StudioUploader.ps1 -KitRoot 'D:\VideoBatch\VideoBatch'
   ```

   Скрипт сохраняет резервную копию заменяемых файлов и ставит EXE, DLL и JS вместе. Не брать исторический EXE из корня репозитория. Не удалять настройки, аккаунты, подписи, историю, Node, FFmpeg или медиа.

   Вместо локальной сборки доступен артефакт **VideoBatch-Subtitle-Upload-Update** успешного workflow **Subtitle presets and upload preparation**. Распаковать отдельно от установленного приложения и запустить из него тот же `scripts/Sync-StudioUploader.ps1` с путём к установленному комплекту.

3. Открыть приложение. В «Комментарии» проверить сохранённую подпись и её предпросмотр с сегодняшней датой. Для другого формата метки явно использовать `{ddMM}`; остальные произвольные числовые коды намеренно не переписываются.
4. Выбрать один собственный отложенный ролик, нажать «Опубликовать». Ожидаемые этапы: версия модуля → выбор Public → подтверждение доступа → открытие YouTube → подтверждение комментария.

## Проверки

Браузерные тесты `tests/browser/youtube-owner-publish.js` воспроизводят RU/EN-окно со скриншотов, скрытые до раскрытия радиокнопки, задержку активности Publish, два ролика подряд, сохранение через Done + Save, прямую публикацию, повтор без дубликатов и ошибку сохранения без отправки комментария. Существующие `tests/browser/studio-state-flow.js` проверяют прежнюю цепочку загрузки.

Windows workflow также собирает EXE и запускает `YouTubeOwnerPublishTests`: подстановка даты, сохранение текста/состояния, отдельные подписи аккаунтов, границы нативных окон. Тесты изолированы; реальные аккаунты Dolphin и публикации пользователя ими не затрагиваются. Проверка на ПК пользователя выполняется после установки, по шагу 4.
