## 2. Модель рабочего пространства

Главная = сохранённые рабочие пространства + создание нового + последние результаты. Не повторный выбор сценария при каждом запуске. Существующие вкладки профилей сборки (RU, EN, Inst, TikTok, TEST, custom) должны оставаться связаны с настоящими идентификаторами, журналами, заголовками, папками и настройками. Не считать каждый профиль новой независимой сущностью данных. Оболочка проекта может ссылаться на существующий профиль/проект/пакет. Раздельные движки не объединять искусственно.

Режим быстрого запуска: открыть сохранённый профиль → добавить/заменить материалы → исправить строки, требующие внимания → проверить результат → собрать. Мастер первого запуска только для нового проекта и может быть закрыт без потери черновика. Постоянная панель запуска одна. Не дублировать кнопки в шапке, подвале и модальных окнах.

## 4. Макет главной и рабочих экранов — решения, предлагаемые по результатам аудита

### Главная
- Сохранённые проекты сверху, поиск и компактный список/плитка, один CTA «Новый проект». Последний запуск, реальный статус, кнопка «Открыть». Без фальшивых счётчиков.
- Новый проект: тип выбирается по результату, а не по модулю. «Разделённый экран», «Вступление и комментарии», «Перевод речи», «Конструктор сцен», «Обработка», «Нарезка». Типы — оболочки над существующими модулями.
- Не заставлять выбирать формат до входа, если сохранённый профиль уже определяет его. Новый проект получает формат через текущий диалог.

### Массовый креатив — ключевой экран
- Шапка: проект, формат, сохранённый пресет. Вся таблица исходников остаётся на экране. Одна строка = один исходник с миниатюрой, ссылкой/именем, комментариями, текстом, озвучкой, результатом. Статус берётся из фактической подготовки.
- Общие настройки рядом с таблицей: «Голос», «Язык», «Оформление», «Музыка», «Заголовки». Клик открывает полноценный редактор соответствующей сущности. Не дублировать ползунки масштаба в таблице.
- «Подготовить» — только реальная команда существующей подготовки, если доступна отдельно; иначе показывать этапы штатного запуска. «Собрать» — существующий RunBatch. Нельзя выдавать новую кнопку за реализованную возможность без подключения.
- Для выбранного ролика: раскрываемая карточка трёх комментариев, текст вступления, прослушивание, редактирование. Применение ко всем — отдельная команда с выбором полей; не перетирать индивидуальные данные.
- Полный холст открывается командой «Монтаж»/двойным нажатием, показывает выбранную стадию. Точные значения за контекстной кнопкой. Не путать четыре стадии креатива с четырьмя сценами конструктора.

### Конструктор
- Полноценный постоянный холст (соотношение сторон сохраняется, окно не растягивает содержимое). Нижняя лента сцен, контекстный список слоёв. Область вне кадра доступна при редактировании, результат обрезается по рамке.
- Слои и варианты различаются визуально: слой — строка; набор вариантов — счётчик и миниатюры в отдельной панели. Общие материалы не смешивать с собственными файлами сцены.
- Разделённый экран использует тот же монтажный фундамент, но показывает только два источника и настройки раскладки, не создавая второй движок.

### Перевод
- Таблица таймкодов, оригинала, перевода; отдельные команды распознавания, перевода, озвучивания/сборки; существующий автоматический запуск — быстрый вариант. Монтаж открывается отдельной вкладкой текущего проекта.
- Не выдавать перевод текстов креатива за перевод оригинала. Их композиция — отдельная задача после тестов совместимости, не часть чистого редизайна.

### Обработка
- Слева список видео, справа категории параметров и пресеты; большая область сравнения оригинала с пробным результатом. Скрывать неактивные настройки только визуально, оставлять доступ через поиск. Полная совместимость ProcessingDialog обязательна.

### Результаты
- Отдельные сущности: готовые файлы, история рецептов и диагностические отчёты. История не является проверкой авторских прав или гарантией прохождения платформенных проверок. Использовать только собственные или разрешённые материалы.

## 5. Визуальный контракт

Графит #18191B, поверхность #232529, граница #3A3C42, основной текст #F1F1F0, вторичный #A6AAB2, светлая первичная кнопка #E4E5E8, акцент #8D9EB7. Слабый холодный градиент только на общей оболочке. Стекло имитировать слоями и тонкими рамками, не накладывать блюр на активный видеохолст. В таблицах — нейтральные строки, цвет только у статуса. Использовать Segoe UI, единый набор монохромных иконок. Не вставлять рекламную иллюстрацию в каждую функциональную строку. Рабочий холст и миниатюры — самые контрастные области.

Навигация 196–220 логических px; в редакторе сворачивается до 56–64. Базовые отступы 8/12/16/24. Элементы управления 36–42 px; крупные карточки только при выборе типа проекта/пресета. Диалоги: фокус, Esc, Enter, отмена без изменений, закреплённый футер, прокрутка содержимого. Не открывать модалку для действия, которое можно выполнить одним кликом. Настройки объекта должны появляться только после его выбора. Масштаб холста и масштаб объекта — разные величины.

## 6. Условия приёмки

1. До изменений получить полный перечень команд из исходников и из живого EXE (включая контекстные меню и modal dialogs). Для каждой: существующий control/handler, данные, новое место, тест. Этот документ — стартовая карта, а не завершённый реестр.
2. Сначала перенести тему и оболочку. Не менять namespace, пути данных, API, файлы проектов, историю и рендер. Старые рабочие панели доступны до завершения проверок.
3. Для каждого режима воспроизвести реальный сценарий от сохранённого проекта до результата, включая отмену/ошибку/повторный запуск, сохранение настроек и выбор файлов. Проверить на Windows при разных DPI и размерах окна.
4. Не менять алгоритмы сборки или допускать потерю параметров ради простоты. Новые функции и изменения модели данных — отдельный согласованный этап.
5. Не считать ни статичный HTML, ни дизайн-аудит доказательством работы рендера, API, LLM или публикации. Проверять результаты на действующих движках и тестах репозитория.

### Контракт сохранения функциональности — обязательный стоп-критерий

- Источник истины: фактическое поведение действующего Windows-приложения и закреплённый срез исходников. Аналоги — только источник UI-паттернов, не требований к продукту.
- Ни один действующий обработчик, пункт меню, флаг, сохранённый профиль, пресет, формат, история, результат, путь, интеграция или ограничение не удаляется по субъективному решению дизайнера.
- Новая оболочка не должна требовать повторного ввода данных из сохранённых проектов. Новые названия — визуальные алиасы, а не новые схемы хранения.
- До миграции сформировать реестр `старый экран → контроль/Name → обработчик → поля модели/хранилище → новый экран → тест → статус`. Для всего, что не подтверждено, статус `не проверено`, не `готово`.
- Сохранить исходные панели и возможность вернуться к ним до успешной проверки функционального паритета. Не заменять рабочий EXE демонстрационной сборкой.
- Не переносить фиктивные данные из прежних HTML-макетов. V1–V4 — отклонённые эксперименты по компоновке, не источник функциональных требований.

## 8. Открытые вопросы, которые нельзя решить только дизайном

1. Полноценный перевод речи исходника внутри `CreativeRender` не подтверждён: в `CreativePreparation.TranslateTextsAsync` переводятся четыре текста (вступление и три комментария). Полный перевод реализован отдельно в `VideoTranslationEngine`. Объединение этих процессов требует технической задачи, а не новой галочки.
2. В `CreativeBatchRunner` проверяется длительность вступительной озвучки до 3 секунд; увеличивать лимит до 4 секунд без отдельной проверки нельзя.
3. `AssemblySplit` ограничивает долю деления кадра диапазоном 25–75%; холст должен соблюдать настоящие ограничения, а не демонстрационный диапазон из прошлых версий.
4. История связок разделена по областям, включая общую и пользовательские. Не доказано, что существует автоматическая сквозная проверка каждого результата со всеми остальными проектами и режимами. Нельзя обещать глобальное отсутствие повторов.
5. Визуальный и звуковой анализ сравнения имеет отдельные поля и может быть неполным. Отображать проценты только при наличии соответствующего отчёта. Это диагностические метрики, не показатель соответствия правилам платформ или авторским правам.
6. Полный реестр обработчиков, живые тесты Windows и измерение удобства на реальных ежедневных задачах остаются обязательными до принятия дизайна. Данный аудит — промежуточный артефакт, не финальный макет.
